# ikko コマンド設計書

## 概要

現在開いているPowerPointのスライド上で、1行ずつ別々のテキストボックスに
分割されてしまったテキストを、**1つのテキストボックス（複数段落）に合体する**
`tools ikko` サブコマンド。

解決したい問題:

- SVGを取り込んで「図形に変換」すると、1行=1つのテキストボックスとして
  バラバラに分割される。見た目は1つの段落なのに、実体は行数ぶんの
  オブジェクトになっているため、後からの編集（文章の書き換え、まとめての移動、
  フォント変更）が極端に面倒になる
- グループ化では「複数オブジェクトのまま束ねる」だけで、テキストとして
  1つにはならない。実際に1つのテキストボックスに合体させたい

サブコマンド名・単体エントリーポイント名ともに `ikko`
（`pyproject.toml` の `[project.scripts]` に `ikko = "tools.cli:run_as_subcommand"` を追加）。
「一個にまとめる」から。短く叩きやすい名前を優先している（`vv` と同じ流儀）。

## 対象範囲

| 実行時の状態 | 対象 |
|---|---|
| シェイプが選択されている | **選択されているシェイプのみ** |
| 選択されていない | **アクティブスライド1枚のみ** |

- プレゼンテーション全体を一括処理する経路は持たない。誤って全スライドを
  書き換える事故を避けるため、既定の対象は常に「今見ている1枚」に限定する
- 判定は `Application.ActiveWindow.Selection.Type` で行う（実機検証済み）:
  - `2`（`ppSelectionShapes`）: 選択あり → `Selection.ShapeRange` を対象にする
  - それ以外（`0`=選択なし, `1`=スライド選択, `3`=テキスト選択）:
    `Application.ActiveWindow.View.Slide` のシェイプ全体を対象にする

## 元に戻す（Undo）

**処理を開始する直前に `Application.StartNewUndoEntry()` を必ず呼ぶ。**

これは利便性ではなく**事故防止のための必須要件**である。実機検証で以下を確認した:

| 条件 | 1回のCtrl+Zの結果 |
|---|---|
| `StartNewUndoEntry()` を呼ばない | **スライドの追加まで巻き戻り、スライドごと消滅した**（`Slides.Count`が0になった） |
| `StartNewUndoEntry()` を呼ぶ | **合体処理のみが巻き戻り**、分割されていたシェイプが元の個数・元のテキストで完全復元された |

- COM経由の変更はPowerPointのUndo履歴に入るが、境界を打たないと
  1回のUndoがどこまで巻き戻るかを制御できない
- 境界を打てば「`ikko`の処理全体」がUndoの1単位になり、
  利用者はCtrl+Z一回で確実に元の状態へ戻せる
- この呼び出しを省略すると、利用者が「1つ戻したいだけ」でCtrl+Zを押した際に
  想定外のスライド削除まで巻き戻る危険があるため、実装時に省略してはならない

ツール側でのバックアップファイル作成やロールバック機構は持たない
（PowerPointのUndoに正しく乗せることで十分な復元手段が確保できるため）。

## 合体の判定ルール

**処理順序: まず「対象から除外するシェイプ」を取り除き、残ったシェイプだけを
左端座標→上端座標の順にソートしてから、隣接ペアの判定に進む。**
除外を後回しにすると、除外されるはずのシェイプ（複数段落を持つテキストボックス等）
を挟んで実際には離れている2つのシェイプが「隣接」と誤判定される
（例: A・B・Cが縦に並び、Bが複数段落で除外対象の場合、除外を先に行えば
AとCが直接比較されて行送りが大きすぎるため別クラスタになるが、
除外とソートの順序を誤ると挙動が不安定になる）。

除外・ソート後、隣接する2つが以下の条件を
**すべて**満たす場合に「同じ段落の連続する行」とみなして同一クラスタにまとめる。

1. フォント名が一致
2. フォントサイズが一致
3. 太字（Bold）設定が一致
4. 文字色が一致
5. 左端（`Left`）座標がほぼ一致（許容誤差 `LEFT_TOLERANCE` 以内）
6. 行送り（`Top` の差）がフォントサイズに対して妥当な範囲内
   （`size * LINE_STEP_MIN_RATIO` 以上 `size * LINE_STEP_MAX_RATIO` 以下）

### 座標の単位はポイント

**COMの `Shape.Left` / `Top` / `Width` / `Height` はポイント単位である**
（`python-pptx` のEMU単位とは異なる。実機検証で `Left=100.0` を設定して
`100.0` が返ることを確認済み）。

したがって許容誤差の既定値はポイント基準で定める:

```python
LEFT_TOLERANCE = 1.0        # ポイント。左端のわずかなズレを許容する
LINE_STEP_MIN_RATIO = 0.8   # 行送りがフォントサイズの何倍以上なら妥当か
LINE_STEP_MAX_RATIO = 2.2   # 行送りがフォントサイズの何倍以下なら妥当か
```

- 行送りの判定に **`Height` を使わない**理由: テキストボックスの `Height` には
  PowerPoint既定の内部余白が含まれ、実際の行間より大きく報告される
  （隣接ボックス同士が見た目上わずかに重なる）。`Top` 同士の間隔を
  フォントサイズと比較する方式にすることで、この影響を受けずに判定できる
- 上限（`LINE_STEP_MAX_RATIO`）を設ける理由: 離れた位置にある無関係な
  テキストボックスまで巻き込んで合体しないようにするため
- これらは `--left-tolerance` / `--line-step-min` / `--line-step-max` の
  オプションで上書きできるようにする（スライドのデザインによって
  適切な閾値が変わるため）

### 対象から除外するシェイプ

以下は判定の対象に含めない:

- テキストフレームを持たないシェイプ（画像、線、矢印など）
- テキストが空、または空白のみのシェイプ
- **すでに複数段落を持つテキストボックス**（`Paragraphs().Count != 1`）。
  合体済み、あるいは元から複数行のテキストボックスとみなしてそのまま残す
- フォント情報が取得できないシェイプ

### フォント情報の取得形式

実機検証で確認した戻り値の形式に合わせて比較する:

- `TextRange.Font.Bold` は `True`/`False` ではなく **`0` / `-1` の整数**で返る
- `TextRange.Font.Color.RGB` も**整数**で返る
- 段落揃えは `TextRange.ParagraphFormat.Alignment`（整数）

いずれも整数同士の比較で足りるため、真偽値へ変換せずそのまま突き合わせる。

## 合体処理

クラスタ内のシェイプが2つ以上ある場合のみ処理する（1つだけなら何もしない）。

1. クラスタ内の各シェイプのテキストを、ソート順（=表示上の行順）に取得する
2. クラスタ全体の外接矩形を計算する
   （`Left` の最小、`Top` の最小、右端の最大、下端の最大から幅・高さを算出）
3. **先頭のシェイプ**に、全行を結合したテキストを設定する
4. 先頭シェイプの位置・サイズを外接矩形に合わせる
5. 先頭以外のシェイプを `Shape.Delete()` で削除する

### 複数行の設定方法

**行の区切りには `"\r"`（CR）を使う。**

`TextRange.Text` に代入する文字は、実機検証で以下の挙動を確認している
（`outline` コマンドの設計時に検証した結果と同一）:

| 代入した改行文字 | 段落として分かれるか |
|---|---|
| `"\n"`（LF） | されない（1段落のまま潰れる） |
| `"\r"`（CR） | **される**（意図通り複数段落になる） |
| `"\r\n"`（CRLF） | される（`"\r"` に正規化される） |
| `"\v"`（垂直タブ） | されない |

したがって各行を `"\r".join(lines)` で連結して一括代入する。
`python-pptx` のように段落を1つずつ `add_paragraph()` する必要はない。

### 書式の再適用

`TextRange.Text` への代入後、クラスタ先頭シェイプの書式が失われる場合があるため、
判定時に取得した代表スタイル（フォント名・サイズ・太字・色・段落揃え）を
テキストレンジ全体に再設定する。

## 出力・ログ

処理内容を `common/logging.py` 経由でログに出す:

- 対象範囲（選択シェイプ / アクティブスライド）と対象シェイプ数
- 合体したクラスタ数と、削除したシェイプ数
- 合体が1件も発生しなかった場合はその旨

完了時に標準出力へ1行のサマリを表示する（例: `3個のクラスタを合体しました（8個のシェイプを2個に）`）。

### `--dry-run`

**実際には変更せず、どのシェイプがどうまとめられるかだけを表示するモード**を用意する。

- 閾値（`LEFT_TOLERANCE` 等）がスライドに合っているかを、破壊的な変更なしに
  確かめられるようにするため
- クラスタごとに、合体対象になるシェイプのテキストと座標を一覧表示する
- `StartNewUndoEntry()` も呼ばない（何も変更しないため）

## エラー処理

- **PowerPointが起動していない場合**: `GetActiveObject` が失敗するため、
  「PowerPointでプレゼンテーションを開いた状態で実行してください」と表示して
  エラー終了する。`outline` と違い**新規起動はしない**
  （既にあるスライドを加工するツールであり、空のプレゼンを作っても意味がないため）
- **プレゼンテーションが開かれていない場合**: 同様にエラー終了する
- **アクティブウィンドウがない場合**（スライドショー実行中など）: エラー終了する
- **対象シェイプが0個の場合**: 「対象になるテキストボックスがありません」と
  表示して正常終了する（エラーにはしない。合体すべきものが無いだけであり、
  異常事態ではない）
- **合体対象のクラスタが0件だった場合**: 「合体できる組み合わせが
  見つかりませんでした」と表示し、閾値オプションの存在を案内して正常終了する
- **COM操作中に例外が発生した場合**: 例外内容を含めたエラーメッセージで終了する。
  途中まで合体された状態が残るが、`StartNewUndoEntry()` により
  Ctrl+Z一回で開始前の状態に戻せる旨をメッセージに含める

## セキュリティ方針との整合（CLAUDE.md）

- **COM操作は `pywin32` の公開APIのみ**を使う。`python-pptx` は
  「開いているファイル」を操作できないため本コマンドでは使わない。
  OOXMLの直接編集・生のWindowsフック・メモリ改ざん・プロセスインジェクションは行わない
- **キー入力の自動送信・グローバルキーフックは行わない。**
  実行トリガーは利用者のコマンド実行のみ
- **常駐・バックグラウンド監視をしない。** 実行のたびに1回だけ
  スライドを読んで加工し、終了する
- **外部通信は発生しない**（すべてローカルのPowerPointへのCOM操作のみ）
- 何を対象にし、何を合体・削除したかを `common/logging.py` 経由でログに出し、
  動作が不透明にならないようにする

## 他コマンドとの関係

`outline` と同じくPowerPointをCOMで操作するコマンド。役割は対照的:

| コマンド | 役割 |
|---|---|
| `outline` | クリップボードのテキストから**スライドを新規に作る** |
| `ikko` | すでにあるスライド上の**バラバラなテキストボックスを1つにまとめる** |

PowerPoint COM接続の取得処理（`GetActiveObject`、アクティブウィンドウ・
プレゼンテーションの特定、エラーハンドリング）は `outline`・`ikko`・`mokuji`
の3コマンドで共通するため、`common/powerpoint.py` に切り出して共用する。
**本節が3コマンド共通の契約の正本であり、`outline.md`・`mokuji.md`は
本節を参照する。**

```python
class PowerPointNotRunningError(RuntimeError):
    """起動中のPowerPointが見つからない場合に送出する。"""

class NoActivePresentationError(RuntimeError):
    """PowerPointは起動しているが、開いているプレゼンテーションが
    ない場合（Presentations.Count == 0）に送出する。"""

def get_running_powerpoint():
    """起動中のPowerPoint Applicationを取得する。

    GetActiveObject("PowerPoint.Application") を試み、失敗した場合は
    新規起動せず PowerPointNotRunningError を送出する。新規起動が
    必要かどうかの判断はコマンド側（outline）に委ねる。
    """

def get_active_presentation(app):
    """アプリケーションのアクティブウィンドウのプレゼンテーションを取得する。

    Application.ActiveWindow.Presentation を返す。
    Presentations.Count == 0 の場合は NoActivePresentationError を送出する
    （ActiveWindow自体が存在しないため）。
    """
```

- `get_running_powerpoint()` は「取得を試みるだけ」で新規起動はしない。
  `outline` は `PowerPointNotRunningError` を捕捉して独自に
  `Dispatch` ＋ `Presentations.Add()` を行い、`ikko`・`mokuji` は
  同じ例外をそのままエラー終了に使う、という形で分岐する
- 両関数とも**例外を送出する契約**に統一する（`None`を返す設計にはしない）。
  呼び出し側で `if presentation is None:` のようなnullチェックを
  重ねるより、`try/except`で分岐を一箇所にまとめられるため
- `ikko` はさらに `Application.ActiveWindow.Selection` を参照するが、
  これは対象範囲の判定（選択 or アクティブスライド）専用のロジックであり
  `ikko.py` 側に置く（`mokuji`・`outline`は選択状態を見ないため
  共通モジュールには含めない）

## テスト方針

判定ロジック（クラスタリング）はCOMに依存しない純粋関数として
`common/shape_cluster.py` に切り出し、`tests/common/test_shape_cluster.py` で
座標・フォント情報を持つ単純なデータクラスを使ってテストする。
`tests/processing/test_ikko.py` ではCOMオブジェクトを `MagicMock` でモックする。

### クラスタリングの判定

- フォント名・サイズ・太字・色がすべて一致し、左端が揃い、行送りが範囲内の
  隣接シェイプが1つのクラスタにまとまること
- **フォント名が違う**シェイプは別クラスタになること
- **フォントサイズが違う**シェイプは別クラスタになること
- **太字設定が違う**シェイプは別クラスタになること
- **文字色が違う**シェイプは別クラスタになること
- **左端が `LEFT_TOLERANCE` を超えてずれている**シェイプは別クラスタになること
- 左端のズレが `LEFT_TOLERANCE` 以内なら同一クラスタになること（境界値）
- **行送りが `LINE_STEP_MIN_RATIO` 未満**（重なっている）なら別クラスタになること
- **行送りが `LINE_STEP_MAX_RATIO` を超える**（離れすぎ）なら別クラスタになること
- 行送りが上限・下限のちょうど境界にある場合の挙動（境界値）
- フォントサイズが取得できない（`None`）場合、行送り判定が成立せず
  別クラスタになること
- シェイプが**左端→上端の順にソート**されてから判定されること
  （入力順がバラバラでも結果が同じになること）
- 3つ以上の連続するシェイプが1つのクラスタにまとまること
- 単独のシェイプ（クラスタサイズ1）は合体対象にならないこと

### 対象シェイプの絞り込み

- テキストフレームを持たないシェイプが除外されること
- テキストが空・空白のみのシェイプが除外されること
- **すでに複数段落を持つテキストボックスが除外されること**
- フォント情報が取得できないシェイプが除外されること

### 対象範囲の判定（モック）

- `Selection.Type == 2` のとき `Selection.ShapeRange` が対象になること
- `Selection.Type == 0`（選択なし）のとき、アクティブスライドの
  シェイプ全体が対象になること
- `Selection.Type == 1` / `3` でもアクティブスライドが対象になること

### 合体処理（モック）

- **`StartNewUndoEntry()` が処理開始前に呼ばれること**（省略すると
  スライドごと消える危険があるため、退行検知として重要）
- クラスタ内の先頭シェイプに、全行が `"\r"` 区切りで結合されて設定されること
- 行の順序が表示順（左端→上端のソート順）になっていること
- 先頭以外のシェイプに対して `Delete()` が呼ばれること
- 先頭シェイプの `Left` / `Top` / `Width` / `Height` が
  クラスタ全体の外接矩形に設定されること
- 代表スタイル（フォント名・サイズ・太字・色・段落揃え）が
  テキスト設定後に再適用されること
- クラスタサイズが1の場合、`Delete()` もテキスト変更も呼ばれないこと

### `--dry-run`

- `--dry-run` 指定時、`Delete()` やテキスト変更が一切呼ばれないこと
- **`--dry-run` 指定時、`StartNewUndoEntry()` も呼ばれないこと**
- クラスタの内容（テキストと座標）が表示されること
- **シェイプが選択された状態で`--dry-run`を指定した場合**、対象範囲は
  選択シェイプに絞り込まれた上でクラスタ内容が表示され、かつ
  `Delete()`・テキスト変更・`StartNewUndoEntry()`のいずれも
  呼ばれないこと（対象範囲の絞り込みと`--dry-run`が両方同時に
  効くことの確認）

### エラー処理のテスト

- PowerPointが起動していない場合、新規起動を試みずエラー終了すること
- プレゼンテーションが開かれていない場合にエラー終了すること
- 対象シェイプが0個の場合、エラーではなく正常終了（メッセージ表示）すること
- 合体クラスタが0件の場合、正常終了し閾値オプションが案内されること
- COM例外時に、Ctrl+Zで戻せる旨を含むエラーメッセージが出ること
