# mdtsv コマンド設計書

## 概要

クリップボード上の **Markdownの表 ↔ TSV** を相互変換する `tools mdtsv` サブコマンド。

解決したい問題:

- **Markdownの表をExcelに貼るとセルに分割されない**（タブ区切りでないため）
- **Excelからコピーした表をMarkdownの表にしたい**

`clipmd`（Markdown ↔ リッチテキスト）から分離した独立コマンド。
`clipmd` は文書全体の形式変換を扱い、こちらは**表とTSVの変換だけ**を扱う。

サブコマンド名・単体エントリーポイント名ともに `mdtsv`
（`pyproject.toml` の `[project.scripts]` に `mdtsv = "tools.cli:run_as_subcommand"` を追加）。

## 変換方向は自動判別

引数なしで実行し、クリップボードの内容から変換の向きを決める。判定は上から順に評価する。

| # | 条件 | 判定 | 変換 |
|---|---|---|---|
| 1 | `CF_UNICODETEXT` が**Markdownの表**として解釈できる | 表がコピーされている | Markdownの表 → TSV |
| 2 | `CF_UNICODETEXT` が**TSV**として解釈できる | 表計算ソフト等からコピーされている | TSV → Markdownの表 |
| 3 | 上記いずれでもない | 変換対象なし | エラー終了 |

判定はすべて `CF_UNICODETEXT`（プレーンテキスト）の内容だけで行う。

**`CF_HTML` は一切見ない。** ExcelでコピーするとTSVと`CF_HTML`の両方が入るが、
Excelが吐くHTMLは`<style>`やセル書式が大量に付くため、
**TSVから組み立てた方が結果が綺麗**になる。よってTSV側だけを使う
（HTMLの表をMarkdownにしたい場合は `clipmd` の役割）。

どちらの向きに変換したかを `common/logging.py` 経由でログに出す。

### Markdownの表かの判定（判定1）

- 空行を除いた全行が `|` で始まり `|` で終わること
- 2行目が区切り行（`|---|---|` 形式）であること

### TSVかの判定（判定2）

- 空行を除いた**全行にタブが1つ以上含まれる**こと

タブが無い行が混ざっている場合はTSVとみなさない
（単なる文章をTSVとして扱って1列の表にしても意味がないため）。

列数が行によって異なっていてもTSVとして受け付ける
（表計算ソフトの選択範囲によっては列数が揃わないことがあるため）。

### 向きの明示指定

自動判別を上書きできる。**オプション名は出力側の形式を表す**。

| オプション | 変換 | 用途 |
|---|---|---|
| `--to-tsv` | 入力をMarkdownの表とみなし → TSV | Excelにセル分割された状態で貼りたい |
| `--to-table` | 入力をTSVとみなし → Markdownの表 | Excelからコピーした表をMarkdownにしたい |

- `--to-tsv` 指定で内容がMarkdownの表として解釈できない場合はエラー終了する
- `--to-table` 指定時は、タブが無い行があってもTSVとして扱う
  （1列の表になるが、利用者が明示的に指定した以上その通りに動かす）
- 自動判別と異なる解釈をした場合はその旨をログに出す

## 出力

**変換結果はクリップボードの `CF_UNICODETEXT` に書き戻すのみ**でファイルは作らない。

`CF_HTML` はセットしない。

- TSVを`CF_HTML`にする意味がない
- Markdownの表をHTMLにするのは `clipmd`（Markdown → リッチテキスト）の役割

## 変換仕様

### Markdownの表 → TSV

- 区切り行（`|---|---|`）は**出力しない**（Excelに不要な行が入るのを防ぐ）
  - 「区切り行らしい見た目の行」を無条件に捨てるのではなく、**まず入力を
    空行で表のブロックに分割し、各ブロック内の2行目だけを区切り行として
    除去する**。データセルの値がたまたまハイフンやコロンのみ
    （例: `| - | - |`）で構成されていても、区切り行と誤認してデータ行ごと
    消してしまわないようにするための判定方法。「次の行が区切り行の形式か
    どうか」だけをフラットに見る実装では、データ行の直後にこの形式の行が
    来た場合に誤って消してしまう回帰が実際に発生したため、空行によるブロック
    分割＋ブロック内の行番号という、より確実な位置判定に変更した経緯がある
- 各セルの前後の空白を除去し、タブで連結する
- セル内のパイプのエスケープ（`\|`）は、素の `|` に戻す
- **セル内の改行はTSVで表現できない**ため、`<br>` があればスペースに置き換える
  （変換で情報が変わった旨をログに出す）
- 列の配置指定（`---:`）は失われる。TSVに配置の概念がないため割り切る

#### 表が複数ある場合

空行を挟んで表が2つ以上並んでいる場合は、**すべての行をつなげて1つのTSVとして出力する**。

- 2つ目以降の表の区切り行も出力しない（区切り行はすべて捨てる）
- 2つ目以降のヘッダー行はデータ行として出力される
  （Excelに貼ってから利用者が判断すればよく、行を捨てる方が害が大きい）
- 列数が異なる表が並んでいる場合も、そのままつなげる
  （TSVは列数が揃っている必要がないため）
- 表が複数あった場合はその旨をログに出す

### TSV → Markdownの表

- 1行目をヘッダー行として扱い、その下に区切り行（`| --- |`）を挿入する
- **セル内のパイプ `|` は `\|` にエスケープする**（表が壊れるため必須）
- 行によって列数が異なる場合は、**最大列数に合わせて空セルで埋める**
  （Markdownの表は列数が揃っていないと崩れるため）
- Excelのセル内改行（TSVではセルがダブルクォートで囲まれ、内部に改行が入る）は
  `<br>` に置き換える。標準ライブラリの `csv` モジュールを `delimiter="\t"` で使い、
  クォート内の改行を正しく扱う
- 桁揃えは行わない（整形が必要なら `clipfmt` を続けて実行する。`doc/clipfmt.md` 参照）

## エラー処理

- `CF_UNICODETEXT` が無い場合: 「変換できるテキストがありません」と明示してエラー終了
- Markdownの表でもTSVでもない場合: どちらとしても解釈できない旨を明示してエラー終了
  （何を期待しているかが分かるメッセージにする）
- 変換結果が空文字列になった場合: エラー終了する
  （空をクリップボードに書き込むと元の内容を失うだけで害しかない）

## セキュリティ方針との整合（CLAUDE.md）

- クリップボードの読み書きは `win32clipboard` の公開APIのみ。実行時に1回だけ読み書きする
- 外部通信は発生しない（変換はすべてローカル処理）
- ファイルの作成・削除は行わない
- どちらの向きに変換したか、情報が失われた箇所をログに出す

## 依存

**追加の依存はない。** 変換は標準ライブラリ（`csv`）と自前の文字列処理だけで完結する。
`markdown-it-py` などのパーサは使わない（表の行を素直に扱う方が単純で確実）。

## 他コマンドとの関係

| コマンド | 役割 |
|---|---|
| `clipmd` | Markdown ↔ リッチテキスト の**文書全体の形式変換** |
| `mdtsv` | Markdownの表 ↔ TSV の**表だけの変換** |
| `clipview` | Markdown/HTML を**ブラウザで表示** |
| `clipfmt` | Markdown を**整形**（形式は変えない） |

Excelからコピーした表をMarkdownにして桁も揃えたい場合は、
`mdtsv`（TSV→表）→ `clipfmt`（桁揃え）と続けて実行する。

## テスト方針

`tests/processing/test_mdtsv.py` に以下を用意する。
クリップボードAPIは `monkeypatch` でモックする。

### 変換方向の判定

- Markdownの表がコピーされているとき、表→TSVが選ばれること
- タブ区切りテキストがコピーされているとき、TSV→表が選ばれること
- **`CF_HTML` があっても無視され、`CF_UNICODETEXT` だけで判定されること**
  （Excelからのコピーを想定）
- タブが無い行が混ざるテキストはTSVとみなされず、エラー終了すること
- Markdownの表でもTSVでもない場合にエラー終了すること
- `--to-tsv` / `--to-table` が自動判別を上書きすること
- `--to-tsv` で表として解釈できない入力はエラー終了すること
- 自動判別と異なる解釈をしたときログに出ること

### Markdownの表 → TSV

- 区切り行が出力されないこと
- **データ行のセルがハイフン・コロンのみ（区切り行と同じ見た目）でも、
  そのデータ行が誤って区切り行として除去されないこと**（回帰防止）。
  区切り行直後（表の3行目）に来る場合と、表の最終行に来る場合の
  両方を確認する（後者は一度別の修正方式で回帰したことがある）
- セルの前後の空白が除去されタブ連結されること
- エスケープされたパイプ `\|` が素の `|` に戻ること
- `<br>` がスペースに置き換えられ、その旨がログに出ること
- 列の配置指定 `---:` があっても変換が完走すること
- **空行を挟んで表が2つ並んでいる場合、1つのTSVにつなげられること**
  （すべての区切り行が捨てられ、2つ目のヘッダー行はデータ行として出力されること）
- 表が複数あった場合にその旨がログに出ること
- 列数が異なる表が並んでいてもそのままつなげられること

### TSV → Markdownの表

- 1行目がヘッダーになり区切り行が挿入されること
- **セル内のパイプが `\|` にエスケープされること**
- 行ごとに列数が違う場合、空セルで最大列数に揃えられること
- クォートで囲まれたセル内改行が `<br>` になること
- 桁揃えが行われないこと（`clipfmt` の役割であることの確認）

### 出力

- 変換結果が `CF_UNICODETEXT` に書き戻されること
- **`CF_HTML` がセットされないこと**

### エラー

- `CF_UNICODETEXT` が無い場合にエラー終了すること
- 変換結果が空になる場合にエラー終了すること
