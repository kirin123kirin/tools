# outline コマンド設計書

## 概要

クリップボードにコピーしたアウトライン（構成案）のテキストから、現在アクティブな
PowerPointプレゼンテーションの末尾にスライド群を自動生成する `tools outline` サブコマンド。

解決したい問題:

- スライドの箇条書き構成案をテキストで練った後、PowerPoint側で1枚ずつ
  「新しいスライド」→レイアウト選択→タイトル入力→本文入力、を繰り返す手間をなくす
- 構成案の記法は普段使っているものをそのまま使いたい（Markdown見出し、
  Excelからのタブ区切りコピペ、単なる空行区切りメモ、のいずれでも）

サブコマンド名・単体エントリーポイント名ともに `outline`
（`pyproject.toml` の `[project.scripts]` に `outline = "tools.cli:run_as_subcommand"` を追加）。

## スコープ

**このコマンドはスライドの追加のみを担当する。目次スライドの生成は別コマンドとして
別途設計する（本書のスコープ外）。** 理由:

- 「アウトラインからスライドを流し込む」と「目次を作る」は独立したタイミングで
  使いたい操作である（構成案を分割して何度かに分けて流し込んだ後、最後に一度だけ
  目次を作る、という使い方が自然）
- 1コマンドに両方を持たせると、目次挿入によるスライド番号のずれや、
  「目次はどのタイミングで何回作られるか」の状態管理が複雑になる
- 単純さを優先する既存の設計方針（`vv`・`profiler`等）に揃える

## 実行環境・依存ライブラリ

- **`pywin32`**: PowerPointのCOM操作（`win32com.client`）
- **クリップボードのテキスト取得**: 既存の `common/clipboard.py` の
  `get_clipboard_text()` を再利用する（`pyperclip` は新規依存として追加しない。
  `win32clipboard` 経由の同等機能が既にあるため）

### 起動トリガーについて（スコープ外）

`.lnk` にホットキーを割り当てて `pythonw.exe` 経由で起動する運用は、
Windows標準のショートカット機能の範囲内であり本コマンド自体の実装には関与しない。
`.lnk` のホットキーは、それが置かれたフォルダ（デスクトップ等）が
エクスプローラー上で認識されている必要があるというOS標準の制約があるが、
これは運用（README等）の記載事項であり、`outline` コマンドの設計・実装には影響しない。

## 入力: クリップボードのテキスト

引数は取らない。実行するたびにクリップボードの現在のテキストを読む
（`vv`とは逆方向で、`clipmd`等と同じく「クリップボードを読んで処理する」側）。

- クリップボードにテキストがない場合はエラー終了する
  （`common/clipboard.py` の `get_clipboard_text()` が投げる例外をそのまま利用）

### 3つの入力フォーマットの自動判別

以下の優先順位で判定し、上から順に該当するかを確認する。
**いずれにも該当しない場合は空行区切り記法にフォールバックする**
（判定不能によるエラー終了はしない。仕組みを知らないラフなメモでも
何かしらスライドが作られる方を優先する）。

1. **Markdown見出し記法**: いずれかの行が `#` 1〜6個 + 半角スペース + 見出し文字列
   （`^#{1,6} .+`）にマッチする場合、この記法とみなす。
   - 見出し行をタイトルとし、次の見出し行（または末尾）までの間の行をリード文とする
   - 見出しレベル（`#`の数）は区別しない。すべて同格のスライドとして扱う
     （アウトラインの深さをスライド階層に反映する機能は持たない。単純さ優先）
   - 見出し行より前にある本文（前置き）は無視する
2. **タブ区切り記法**: いずれかの行にタブ文字（`\t`）が含まれる場合、この記法とみなす。
   - 1行を1スライドとし、最初のタブより前をタイトル、後ろをリード文とする
   - タブを含まない行は1行1スライド構成の「タイトルのみ」の行として扱う
     （空行はスキップする）
3. **空行区切り（ブロック）記法**: 上記どちらにも該当しない場合、これを使う。
   - 連続する空行でブロックに分割する
   - 各ブロックの1行目をタイトル、2行目以降をリード文とする
   - リード文がない（ブロックが1行のみの）場合は、タイトルのみのスライドとして許容する

### タイトル・リード文の改行の扱い

- **リード文内の改行はそのまま保持する。** タブ区切り形式でタブの後ろに
  複数行ある場合や、空行区切りでブロック内の2行目以降が複数行ある場合も、
  改行を連結・削除せずPowerPointのテキストプレースホルダーに複数行として流し込む
  （箇条書き風の複数行リード文をそのまま活かせるようにするため）。
- タイトルは1行として扱う（タイトル行の内部改行は想定しない）。

### 判定・抽出の実装場所

`common/outline_parse.py`（新規）に切り出す。

```python
@dataclass(frozen=True)
class OutlineItem:
    title: str
    body: str  # 複数行の場合は"\n"区切り。リード文なしなら空文字列

def parse_outline(text: str) -> list[OutlineItem]:
    """3形式を自動判別してOutlineItemのリストを返す。
    Markdown見出し → タブ区切り → 空行区切り（フォールバック）の優先順で判定する。
    """
```

- クリップボードのテキストは改行がCRLF/LF混在しうるため、まずLFへ正規化する
  （`common/textfile.py` の `normalize_newlines()` を再利用、`vv`と同じ方針）
- 判定・抽出のロジックはPowerPoint COM操作と無関係な純粋関数として切り出し、
  ユニットテストしやすくする（COM部分は実機依存でテストしづらいため、
  ロジックの大半をここに寄せる）

## 出力: PowerPointの操作

### 対象プレゼンテーションの特定（共通モジュール）

**アクティブウィンドウのプレゼンテーション**を対象にする。取得には
`common/powerpoint.py` の `get_running_powerpoint()` /
`get_active_presentation()` を使う（関数シグネチャ・例外の契約は
`ikko.md` の「他コマンドとの関係」節を正本とする）。

- `get_running_powerpoint()` は内部で
  `win32com.client.GetActiveObject("PowerPoint.Application")` を試みる
  （新規プロセスを起動する `Dispatch` ではなく、既存の起動中インスタンスを掴む）
- `get_active_presentation(app)` は `Application.ActiveWindow.Presentation`
  を返す（`Application.ActivePresentation` ではなく `ActiveWindow.Presentation`
  を使う。複数のPowerPointウィンドウが開いている場合に「今フォーカスが
  当たっているウィンドウのプレゼンテーション」を優先的に特定するため）
- 複数のプレゼンテーションが開いていても、選択・一覧提示は行わない
  （「今開いて見ている画面」に流し込む、というワンアクションの体験を優先する）

### PowerPointが起動していない・プレゼンテーションがない場合

**新規に起動し、新規プレゼンテーションを作成して続行する。**
`ikko`・`mokuji`は同じ状況をエラー終了とするが、`outline`のみ以下の通り続行する。

- `get_running_powerpoint()` が `PowerPointNotRunningError` を送出した場合、
  `win32com.client.Dispatch("PowerPoint.Application")` で新規起動する
- 起動直後は `Presentations` が空のため、`Presentations.Add()` で
  新規プレゼンテーションを作成する
- 新規起動時は `Application.Visible = True` を明示的に設定する
  （非表示のまま生成すると、利用者が結果を確認できないため）
- `get_active_presentation()` が `NoActivePresentationError` を送出した場合
  （PowerPointは起動しているがプレゼンテーションが1つもない場合）も、
  同様に `Presentations.Add()` で新規作成して続行する
- どちらの経路を通ったか（既存プレゼンテーションに追記／新規作成）を
  `common/logging.py` 経由でログに出す

### レイアウトとスライド追加

- レイアウトは「タイトルとコンテンツ」（`ppLayoutText` 系、レイアウトID: 2、
  `PpSlideLayout.ppLayoutText`）を使う
- 抽出した `OutlineItem` の数だけ、`Slides.Count` を末尾として `Slides.Add()` で追加する
  （`Slides.Add(Index, Layout)` で末尾インデックスを明示指定する。
  `Slides.Count` は追加のたびに変わるため、追加前に取得した件数を起点に
  `count + 1, count + 2, ...` と計算するのではなく、毎回`Slides.Count + 1`を
  インデックスとして使う）
- **この「毎回`Slides.Count + 1`」という同一の式は、新規作成直後の
  空プレゼンテーション（`Slides.Count == 0`）と、既存スライドがある
  プレゼンテーションへの追記のどちらでも実機で動作を確認済み。**
  `Presentations.Add()`直後は`Slides.Count == 0`だが、この状態から
  `Slides.Add(0 + 1, Layout)` を呼んでも例外にはならず1枚目として
  追加され、以降も`Slides.Count + 1`を使い続けるだけで常に末尾に
  正しい順序で積み上がる（分岐は不要）。既存スライドが2枚ある状態から
  追加した場合も、既存スライドの後ろに正しい順序で追加されることを確認済み
- タイトルは `Shapes.Placeholders(1).TextFrame.TextRange.Text`、
  本文（テキストプレースホルダー、インデックス2）は
  `Shapes.Placeholders(2).TextFrame.TextRange.Text` にそれぞれ設定する
- リード文が空文字列の場合、本文プレースホルダーには空文字列を設定する
  （プレースホルダー自体は残るが中身は空、という状態にする。
  プレースホルダーを削除する等の追加操作はしない）

### 複数行リード文の流し込み

**`OutlineItem.body` の `"\n"` は、設定直前に `"\r"`（CR）へ変換する。**
`"\r"` にする理由はPowerPoint実機での検証で確認した挙動による
（PowerPoint 2016 / `win32com` 経由、`TextRange.Text` へ代入した場合）:

| 代入した改行文字 | 段落として分かれるか | 保存後に読み出した`Text`の値 |
| --- | --- | --- |
| `"\n"`（LF） | されない（1段落のまま） | `"\n"`のまま |
| `"\r"`（CR） | **される**（意図通り複数段落になる） | `"\r"`のまま |
| `"\r\n"`（CRLF） | される | `"\r"`に正規化される（COM側がCRLFをCRへ丸める） |
| `"\v"`（垂直タブ） | されない（段落内改行にもならない） | `"\x0b"`のまま |

- `"\n"`単体では改行として扱われず、プレースホルダー内で1行に潰れて表示される
  ため、そのまま代入してはいけない
- 上記はpptx保存→再読み込み後も同じ結果になることを確認済みで、
  実行中だけの一時的な表示ではない
- 実装は「`OutlineItem.body` 内の `"\n"` をすべて `"\r"` に置換してから
  `TextRange.Text` に代入する」という単純な変換で足りる
  （`"\r\n"`が来た場合も、先に`normalize_newlines()`でLFへ統一済みのため、
  この段階では`"\n"`のみを考慮すればよい）

## エラー処理

- クリップボードにテキストがない場合: エラーメッセージを表示して終了する
- クリップボードのテキストからスライドが1件も抽出できない場合
  （空文字列、空白のみ等）: 「アウトラインとして解釈できる内容がありません」
  と表示してエラー終了する（PowerPoint操作は一切行わない）
- COM操作中に例外が発生した場合（PowerPointが処理中に閉じられた等）:
  例外内容を含めたエラーメッセージで終了する。中途半端に追加されたスライドを
  ロールバック（削除）する機能は持たない（COM操作の性質上、途中失敗からの
  巻き戻しは複雑になるため。エラーメッセージで利用者に状況を伝えるに留める）

## セキュリティ方針との整合（CLAUDE.md）

- **COM操作は`pywin32`の公開APIのみ**を使う。`python-pptx`はファイル直接編集
  専用で「開いているファイル」を操作できないため不採用。生のWindowsフック・
  メモリ改ざん・プロセスインジェクションは行わない
- **キー入力の自動送信・グローバルキーフックは行わない。** `keyboard`ライブラリ等の
  常時キー監視は一切使用しない。起動トリガーはOS標準の`.lnk`ホットキー機能に委ね、
  本コマンドは起動された後の1回きりの処理のみを担当する
- **PowerShellは使用しない。** 実行はPython（`pythonw.exe`）のみで完結させる
- **常駐・バックグラウンド監視をしない。** 実行のたびにクリップボードを1回読み、
  PowerPointへの反映が終わり次第終了する。クリップボードを監視し続ける
  実装にはしない
- 何を読み込み、何件のスライドをどのプレゼンテーションに追加したかを
  `common/logging.py` 経由でログに出す

## 他コマンドとの関係

`clip*`系コマンドと同様に「クリップボードを読んで処理する」側だが、出力先が
クリップボードやファイルではなく**PowerPointという外部アプリケーションのCOM経由の
操作**である点が既存コマンドと異なる唯一のコマンド。

## テスト方針

`tests/common/test_outline_parse.py` に、`parse_outline()` の純粋関数部分を
COM非依存でテストする。`tests/processing/test_outline.py` では
PowerPoint COMオブジェクトを `MagicMock` でモックし、`Slides.Add`・
`Placeholders`・`TextRange.Text` への呼び出しを検証する。

### 入力フォーマットの判定・抽出

- Markdown見出し記法: `#`〜`######`（半角スペース付き）の行がタイトルとして認識されること
- Markdown見出し記法: 見出し行より前の前置き本文が無視されること
- Markdown見出し記法: 見出しレベル違い（`#`と`##`が混在）でも同格に扱われること
- タブ区切り記法: タブより前がタイトル、後ろがリード文になること
- タブ区切り記法: タブを含まない行は空行以外タイトルのみのスライドになること
- 空行区切り記法: ブロックの1行目がタイトル、2行目以降がリード文になること
- 空行区切り記法: ブロックが1行のみの場合、リード文なしのタイトルのみになること
- **優先順位の検証**: Markdown見出しとタブの両方を含むテキストはMarkdown見出し
  記法として判定されること
- **フォールバックの検証**: どの記法にも当てはまらないテキスト（見出しもタブも
  ない、空行もない1個の段落など）が空行区切り記法として処理されること
  （1ブロック・1スライドになる）
- 改行の正規化: CRLF/LF混在のクリップボードテキストが正しく解析されること
- リード文内の複数行がそのまま保持されること（結合・削除されないこと）
- クリップボードが空文字列の場合、`OutlineItem`が1件も抽出されないこと

### PowerPoint操作（モック）

- `GetActiveObject`が成功した場合、その`ActiveWindow.Presentation`が
  操作対象になること
- `GetActiveObject`が失敗した場合、`Dispatch`で新規起動し
  `Presentations.Add()`が呼ばれ、`Visible = True`が設定されること
- 抽出件数と同じ回数だけ`Slides.Add`が呼ばれること
- 各スライドで`Placeholders(1)`にタイトル、`Placeholders(2)`に
  リード文が設定されること
- リード文が空の`OutlineItem`では、本文プレースホルダーに空文字列が
  設定されること（例外にならないこと）
- `Slides.Add`が末尾インデックス（既存スライド数+追加順）で呼ばれること
  （既存スライドがある状態に追記した場合も正しい位置に追加されること）

### エラー処理のテスト

- クリップボードが空/取得失敗の場合、エラーメッセージで終了すること
- 抽出結果が0件の場合、PowerPoint操作（`GetActiveObject`等）が
  一切呼ばれずにエラー終了すること
- COM操作中に例外が発生した場合、例外内容を含むエラーメッセージで終了すること
