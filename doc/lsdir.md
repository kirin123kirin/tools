# lsdir コマンド設計ドラフト

> **状態: ドラフト（未確定）** — 末尾の未決事項を確定させてから実装に入る。

## 概要

フォルダ配下を再帰的に走査し、**Excelで集計・フィルタできる表**として一覧を出力する
`tools lsdir` サブコマンド。

解決したい問題:

- フォルダ配下に何がどこに何個あるのか、全体像が把握できない
- `dir /s` や `tree` の出力は列が揃わず、Excelに貼っても並べ替え・絞り込みができない
- サイズ・更新日時・拡張子・階層をまとめて見て、どこが容量を食っているか知りたい

サブコマンド名・単体エントリーポイント名ともに `lsdir`
（`pyproject.toml` の `[project.scripts]` に `lsdir = "tools.cli:run_as_subcommand"` を追加）。

## 出力する列

| 列 | 内容 |
|---|---|
| `source` | どの起点から辿ったか（複数の起点を指定したときの区別用） |
| `type` | 種別。`file` または `dir` |
| `name` | ファイル名・フォルダ名 |
| `fullpath` | フルパス |
| `parent` | 親フォルダのパス |
| `ext` | 拡張子（`.txt` 等。フォルダと拡張子なしは空） |
| `size` | サイズ（既定KB、後述。フォルダ行は空。`--total-size` 指定時は配下の合計） |
| `mtime` | 更新日時（`YYYY/MM/DD HH:MM`） |
| `depth` | 起点からの階層の深さ（起点直下が1） |
| `link` | `.lnk` のリンク先（**`--resolve-link` 指定時のみこの列が出る**。後述） |

- **1回の実行の中では列数を固定**する。行によって列数が変わるとExcelで
  列の意味がずれるため、階層を可変長に展開するようなことはしない
  （階層ごとの集計は `depth` で行う）。
  `link` 列だけはオプションで有無が変わるが、実行単位では固定される
- `source` 列を持つのは、複数の起点を指定したとき `depth=1` が
  別々の起点を指して紛らわしくなるため。起点が1つでも列は出す（列数を固定するため）

### サイズの単位

**既定はKB、小数第2位まで**。`--unit` で切り替える。

| 指定 | 単位 |
|---|---|
| `--unit kb`（既定） | KB（`500` バイト → `0.49`） |
| `--unit b` | バイト数そのまま |
| `--unit mb` | MB |
| `--unit gb` | GB |

- 小数第2位まで残すのは、KB単位だと1KB未満のファイルが0に潰れてしまうため
- Excelで合計するとき誤差が問題になる場合は `--unit b` を使う
- 1KB = 1024バイトとする（1000ではない）

## 走査

### ファイルとフォルダの両方を出す

既定では**ファイルとフォルダの両方**を1回の実行で出力し、`type` 列で区別する。

- 1回実行すれば全体像が分かる。絞り込みはExcelのフィルタで行えばよい
- `--files-only` / `--dirs-only` で出力を絞れる

### 起点の指定

```powershell
lsdir C:\work                  # 1つのフォルダ
lsdir C:\work D:\data          # 複数指定
lsdir C:\work\*.xlsx           # グロブ
```

### 除外

`--exclude` で名前を指定して除外する（既定: `.git` `.svn` `node_modules` `__pycache__`）。

- 指定した名前の**フォルダは配下ごと走査しない**（無駄な走査を避けるため）
- **`~$` で始まるファイルは既定で除外する**（Officeが開いている間に作る一時ファイルで、
  一覧に出ても意味がないため）。`--include-temp` で含められる

### 走査中のエラー

**アクセスできないフォルダがあっても走査全体を止めない。**

- 権限エラー等で読めないフォルダは**警告ログを出してスキップ**し、次へ進む
- 最後に「スキップしたフォルダ数」をログに出す（どこまで見たかが分かるように）
- 起点そのものが存在しない・読めない場合はエラー終了する

### シンボリックリンク・ジャンクション

- 既定では**辿らない**（`type` は `dir`/`file` のまま出し、中身は展開しない）
- 辿るオプションは設けない（循環したときに無限ループする危険があり、
  Windowsのジャンクションでは実際に起きやすいため）

### 重複の除去

複数の起点が入れ子になっている場合（`lsdir C:\work C:\work\sub`）、
同じファイルが複数回出力されうる。**フルパスで判定して重複を除く**。

- 訪問済みのフルパスを記録し、2回目以降はスキップする
- Excelで集計したときに二重カウントしないようにするため
- 判定は `os.path.normcase(os.path.abspath(path))` で正規化した文字列で行う
  （Windowsは大小を区別しないため、`C:\Work` と `C:\work` を同一とみなす）
- 重複をスキップした件数をログに出す

### 0件のとき

**ヘッダーのみ出力して正常終了する。** 空フォルダを指定するのは正常な使い方であり、
エラーにするとバッチ処理で扱いにくいため。

- 起点そのものが存在しない場合は前述の通りエラー終了する
  （「空だった」と「指定を間違えた」は区別する）

### .lnk（ショートカット）のリンク先

**`--resolve-link` 指定時のみ**、`link` 列にリンク先パスを出す。

- 既定で無効にするのは、`.lnk` が多いとファイルごとにCOM呼び出しが発生して遅くなるため
- 解決には `pywin32` の `WScript.Shell`（公開COM API）を使う。
  遅延インポートし、`.lnk` を見つけたときだけ呼ぶ
- 解決に失敗した場合は `link` を空にし、警告ログを出す
  （例外名などをデータ列に混ぜない）
- `--resolve-link` 未指定時は `link` 列自体を出さない

## フォルダ配下の合計サイズ（`--total-size`）

「どのフォルダが容量を食っているか」を知るための機能。**オプション指定時のみ**有効。

```powershell
lsdir C:\work --total-size
```

- 指定時、`dir` 行の `size` に**配下の全ファイルの合計バイト数**を入れる
- 未指定時は `dir` 行の `size` は空

### なぜ既定にしないか

合計サイズを出すには**配下を走査し切ってからでないと値が確定しない**。
つまり全走査が終わるまで1行も出力できない。

- 既定（未指定時）は**見つけた順に出力する**ため、大きなツリーでもすぐ結果が出始める
- `--total-size` 指定時は全走査してから出力するため、待ち時間が発生する

この差を利用者が選べるようにするため、オプトインとする。
**指定時は「集計中」であることをログに出す**（無反応に見えるのを防ぐ）。

## 出力

```powershell
lsdir C:\work                    # 標準出力にTSV
lsdir C:\work -o list.tsv        # TSVファイル
lsdir C:\work -o list.xlsx       # Excel（オートフィルタ付き）
lsdir C:\work --clip             # 結果をクリップボードにTSVでコピー
```

- 既定は標準出力にTSV
- **`--clip` 指定時は標準出力に結果を出さず**、クリップボードにのみ入れて
  短い完了メッセージだけ表示する（`profiler` および `clip*` 系と同じ方針）
- `--encoding` で出力エンコーディングを指定（Windows既定 `cp932`）。
  **`errors="backslashreplace"` を使う**
  （ファイル名に機種依存文字があってもエンコードエラーで落ちないように）

### Excel出力時の書式

- ヘッダー行を太字・罫線付きにし、オートフィルタを設定する
- `size` を数値として書き込む（文字列にすると合計できないため）
- `mtime` を日付書式で書き込む
- 依存は `xlsxwriter`。`.xlsx` 出力時のみ遅延インポートする

## 実装方針

- `os.scandir()` を再帰的に使う。`DirEntry.stat()` は
  **走査中に取得済みの情報を返すため、追加のシステムコールが要らない**
  （大量ファイルで効く）
- ファイルモード（`-rw-r--r--` 形式）は出力しない。
  Windowsでは意味を持つ情報が少なく、列を増やす価値が薄いため
  （必要なら未決事項として再検討）
- 所有者・グループも出力しない（Windowsでの取得はファイルごとのAPI呼び出しになり、
  走査が大幅に遅くなるため。未決事項参照）

## セキュリティ方針との整合（CLAUDE.md）

- 走査は `os.scandir()` の公開APIのみ。ファイル内容は一切読まない（属性だけ）
- 外部通信は発生しない
- 実行のたびに1回走査して終了する。常駐監視はしない
- 走査したフォルダ数・スキップしたフォルダ数・出力先をログに出す

## 他コマンドとの関係

| コマンド | 役割 |
|---|---|
| `lsdir` | フォルダ配下の一覧を表形式で出す |
| `profiler` | 表形式データの各列の統計プロファイルを出す |

`lsdir` の出力を `profiler` にかければ、
「拡張子の種類はいくつあるか」「更新日時が埋まっていない行はあるか」といった
メタな確認もできる（`lsdir C:\work --clip` の後に `profiler` を引数なしで実行する）。

## テスト方針

`tests/processing/test_lsdir.py` に用意する（`tmp_path` に実際のファイル・フォルダを作る）。

### 走査のテスト

- 再帰的に下位フォルダまで走査されること
- 既定でファイルとフォルダの両方が出力され、`type` 列で区別できること
- `--files-only` でフォルダ行が出ないこと
- `--dirs-only` でファイル行が出ないこと
- `--exclude` で指定した名前のフォルダが**配下ごと**除外されること（既定値も検証）
- **`~$` で始まるファイルが既定で除外され、`--include-temp` で含まれること**
- **アクセスできないフォルダがあっても走査が止まらず、警告ログが出ること**
  （`scandir` が `PermissionError` を投げるようモックして検証）
- 起点が存在しない場合はエラー終了すること
- シンボリックリンクを辿らないこと（リンク先の中身が展開されないこと）
- **空フォルダを指定したとき、ヘッダーのみ出力して正常終了すること**
  （エラーにならないこと）
- **起点が入れ子のとき（`C:\work` と `C:\work\sub`）、同じファイルが
  1回しか出力されないこと**
- 大小が異なるパス（`C:\Work` と `C:\work`）が同一とみなされ重複除去されること
- 重複をスキップした件数がログに出ること

### 出力列

- `type` が `file` / `dir` になること
- `mtime` が `YYYY/MM/DD HH:MM` 形式であること
- `ext` が拡張子と一致し、拡張子なしファイルとフォルダで空になること
- `depth` が階層と一致すること（起点直下が1）
- `parent` が親フォルダのパスと一致すること
- **`source` が指定した起点と一致すること**（複数起点で区別できること）
- **すべての行で列数が同じであること**（可変長にしない方針の担保）

### サイズの単位のテスト

- 既定（`--unit kb` 相当）で**KB・小数第2位**になること
  （500バイトのファイルが `0.49` になること）
- `--unit b` でバイト数そのままになること
- `--unit mb` / `--unit gb` で単位が切り替わること
- **1KB = 1024バイトで計算されること**（1000ではないこと）
- フォルダ行の `size` が空であること（`--total-size` 未指定時）

### .lnk の解決

- **`--resolve-link` 未指定時は `link` 列自体が出ないこと**
- `--resolve-link` 指定時に `link` 列が出て、`.lnk` のリンク先が入ること
  （`win32com` はモックし、COM呼び出しの有無を検証する）
- 解決に失敗したとき `link` が空になり、警告ログが出ること
  （例外名がデータ列に混入しないこと）
- **`--resolve-link` 未指定時にCOM呼び出しが発生しないこと**

### 合計サイズ

- `--total-size` 指定時、`dir` 行の `size` が配下の合計バイト数になること
- **入れ子のフォルダで、親の合計に子の合計が含まれること**
- 空フォルダの合計が0になること
- 未指定時は `dir` 行の `size` が空であること
- **未指定時は全走査を待たずに出力が始まること**
  （ジェネレータとして1件目が取れることを検証する）

### 出力形式

- 既定でTSVが標準出力に出ること
- `-o *.xlsx` でExcelになること（`size` が数値として書かれること）
- `--clip` でクリップボードに入ること
- ヘッダーが1度だけ出ること（複数の起点を指定しても重複しないこと）
- **ファイル名に機種依存文字があってもエンコードエラーで落ちないこと**
- **`xlsxwriter` が `.xlsx` 出力以外ではインポートされないこと**

## 未決事項

1. **ファイルモード・所有者の出力**
   Windowsでは `stat.filemode()` の情報量が乏しく、所有者取得は
   `win32security` でファイルごとにAPI呼び出しが必要で遅い。
   現状は出力しない方針だが、実務で必要になったらオプトイン（`--owner`）で
   追加する形でよいか。

2. **巨大ツリーでの実行時間と進捗表示**
   数十万ファイル規模での実測が必要。`--total-size` 指定時は特に待たされるため、
   進捗表示（`--verbose` で一定件数ごとに件数をログ）を付けるか実装時に判断する。

3. **重複除去のメモリ使用量**
   訪問済みパスを全件記録するため、数十万ファイル規模ではパス文字列の
   集合がメモリに乗る。実測して問題があれば、起点が入れ子のときだけ
   記録する等の最適化を検討する。
