# clipview コマンド設計書

## 概要

クリップボード上のMarkdownまたはHTMLを、**デフォルトブラウザでプレビュー表示**する
`tools clipview` サブコマンド。

解決したい問題:

- 書いたMarkdownの見栄えを確認したいが、そのためにエディタやビューアを開くのが面倒
- Webからコピーした断片HTMLがどう見えるのか、その場で確認したい

`clipmd` と同じくクリップボードを入力とするが、**変換結果をクリップボードに戻すのではなく
ブラウザで表示する**点が異なる。

サブコマンド名・単体エントリーポイント名ともに `clipview`
（`pyproject.toml` の `[project.scripts]` に `clipview = "tools.cli:run_as_subcommand"` を追加）。

## 入力の判別

`clipmd` の判定ロジックと同じ考え方で、クリップボードの形式から入力の種類を決める。

| # | クリップボードの状態 | 扱い |
|---|---|---|
| 1 | `CF_UNICODETEXT` の内容が `<svg` で始まる（前後空白許容） | SVGとしてそのままファイルに保存してプレビュー |
| 2 | `CF_HTML` がある | 断片HTMLを取り出してプレビュー |
| 3 | `CF_UNICODETEXT` のみ | Markdownとして解釈し、HTMLに変換してプレビュー |
| 4 | どちらもない | エラー終了 |

**SVGだけは他と扱いが異なり、HTMLに埋め込まずSVGコードをそのままファイルに
書き出す。** ブラウザは`.svg`ファイルを直接開くとSVGとしてネイティブに
レンダリングするため、`<html>`でラップする必要がない。むしろラップして
`<img>`や`<object>`経由で埋め込むと、SVGが持つ本来の表示サイズや
背景の透過が失われることがあるため、**そのまま**渡す方が意図通りに表示される。

HTML/Markdown側の経路では、**得られるのはHTMLの断片（`<body>`の中身相当）である。**
`CF_HTML` から取り出した断片には `<html>` / `<body>` / `<meta charset>` が無く、
Markdownを変換した結果も同様に断片である。
したがって**いずれの場合も、後述のプレビュー用HTMLでラップして完全な文書に仕立てる**。

- `--markdown` / `--html` / `--svg` で入力の解釈を明示指定できる
  （HTMLソースをテキストとしてコピーした場合など）。3つは互いに排他
- `--markdown` / `--html` を指定した場合、`<svg`で始まるテキストであっても
  SVGの自動判定より指定が優先される
- どれとして解釈したかをログに出す

Markdown → HTML の変換は `clipmd` と同じ `markdown-it-py`（`enable("table")` 込み）を使う。
変換処理は `clipmd` と共通化し、`common/` 配下に切り出す。

## 出力（プレビュー用HTML）

### ファイルの置き場所

`%TEMP%\tools_clipview_preview.html` に**固定名で上書き**する。
毎回新規ファイルを作るとゴミが溜まり続けるため、固定名にする。

SVGの場合は同じ考え方で `%TEMP%\tools_clipview_preview.svg` に固定名で
上書きする（拡張子だけが異なる別ファイル。HTMLプレビューと共存できる）。

### キャッシュ対策

固定名にすると、**ブラウザが同じURLを既存タブで開き直さず、古い内容を表示する**恐れがある。
`<meta>` によるキャッシュ制御は再読み込みされなければ効かないため、それだけでは不十分。

そこで**開くURLにキャッシュバスターのクエリを付ける**。

```text
file:///C:/Users/.../Temp/tools_clipview_preview.html?v=<タイムスタンプ>
```

- ブラウザはクエリが異なると別リソースと見なすため、確実に最新内容が読み込まれる
- ファイル自体は固定名のままなので、ゴミは増えない
- `file://` URLにクエリを付けられることは検証済み
  （`Path.as_uri()` で得たURLに `?v=` を連結する）
- 併せて `<meta http-equiv="Cache-Control" content="no-store">` も入れておく（多重の保険）

このコマンドは目的上ファイル生成が必須である（他のコマンドは副作用を持たない方針だが、
ブラウザに渡すにはファイルが必要なため例外とする）。
**どのパスに書き出したかを必ずログに出す**。

### ブラウザの起動

Python標準の `webbrowser.open()` を使う。

- 既定のブラウザが開く。ブラウザを指定する機能は設けない
  （OSの既定設定に従うのが最も予測しやすい）
- `webbrowser` は標準ライブラリなので依存は増えない
- `--no-open` オプションでブラウザを開かず、パスの表示だけにする
  （自動テストや、手動でブラウザに読み込ませたい場合のため）

### HTMLの体裁

プレビューは**読みやすさを目的とする**ため、`clipmd`（貼り付け先で崩れないことを目的とする）とは
方針が異なり、こちらは見やすさのためのスタイルを積極的に当てる。

- 最小限のCSSを `<style>` に埋め込む（外部CDNは使わない。オフラインで動くこと）
  - 本文幅を読みやすい範囲に制限する
  - 表に罫線を引く
  - コードブロックに背景色と等幅フォントを当てる
  - 引用に左罫線を入れる
- **ダークモードに対応する**（`@media (prefers-color-scheme: dark)`）
- 文字コードは UTF-8 を明示（`<meta charset="utf-8">`）
- タイトルは固定文字列（例: `clipview preview`）

凝ったデザインは目的ではないので、素朴で読みやすいスタイルにとどめる。

## エラー処理

- クリップボードに `CF_HTML` も `CF_UNICODETEXT` もない場合: 明示してエラー終了
- 変換結果が空の場合: エラー終了する
  （空のページをブラウザで開いても何も分からないため）
- 一時ファイルの書き込みに失敗した場合: パスを含めたエラーにする

## セキュリティ方針との整合（CLAUDE.md）

- クリップボードの読み取りは `win32clipboard` の公開APIのみ。実行時に1回だけ読む
- **外部通信は発生しない**。CSS/JSは外部から読み込まず、すべてHTMLに埋め込む
  （プレビュー対象のHTMLに外部リソースへの参照が含まれていた場合、
  ブラウザがそれを読み込むことはあるが、それは元のHTMLに由来するものであり
  このツールが通信を追加するわけではない）
- 生成した一時ファイルのパスをログに出し、どこに何を書いたか分かるようにする
- 一時ファイルは固定名で上書きするだけで、削除処理は行わない
  （消し忘れよりも、後から内容を確認できる方が有用）

## 他コマンドとの関係

| コマンド | 役割 |
|---|---|
| `clipmd` | Markdown ↔ リッチテキスト の**文書全体の形式変換** |
| `mdtsv` | Markdownの表 ↔ TSV の**表だけの変換** |
| `clipview` | Markdown/HTML を**ブラウザで表示**（クリップボードは書き換えない） |
| `clipfmt` | Markdown を**整形**（形式は変えない） |

このコマンドだけは**クリップボードを書き換えない**（読むだけ）。
表示して確認するのが目的であり、内容を変えないことが期待される動作である。

## テスト方針

`tests/processing/test_clipview.py` に以下を用意する。
クリップボードAPIと `webbrowser.open` は `monkeypatch` でモックする。

### 入力判別のテスト

- `CF_HTML` があるとき、そのHTMLがプレビューに使われること
- `CF_UNICODETEXT` のみのとき、Markdownとして変換されること
- どちらもないときエラー終了すること
- `--markdown` / `--html` / `--svg` が判別を上書きすること
- **`<svg`で始まるテキスト（前後空白許容）がSVGとして自動判定されること**
- **SVGと判定された場合、HTMLラップされずコードがそのままファイルに
  書き出されること**（`<html>`タグが含まれないこと）
- `<svg`で始まらないテキストはSVGとして扱われないこと
- `--markdown`/`--html`指定時は、`<svg`で始まるテキストでもSVGの
  自動判定より優先されること
- `--svg`指定時にクリップボードにテキストがなければエラー終了すること

### 出力

- `%TEMP%` に固定名でHTMLが書き出されること
- 2回実行しても同じパスに上書きされること（ファイルが増殖しないこと）
- 書き出したパスがログに出ること
- HTMLに `<meta charset="utf-8">` とキャッシュ制御が含まれること
- HTMLにダークモード用の `prefers-color-scheme` が含まれること
- **`CF_HTML` の断片が完全なHTML文書にラップされること**
  （`<html>` / `<body>` / `<meta charset>` が付与され、断片がそのまま書き出されないこと）
- **Markdownから変換した断片も同様にラップされること**
- 外部URLへの参照（`http://` / `https://` から始まる `src` や `href` のCSS/JS読み込み）が
  生成したHTMLの**スタイル部分に含まれないこと**（オフラインで動くことの担保）

### ブラウザ起動

- 既定で `webbrowser.open` が呼ばれること
- `--no-open` 指定時に `webbrowser.open` が呼ばれないこと
- `--no-open` 指定時もパスが表示されること
- **`webbrowser.open` に渡すURLに `?v=` のクエリが付いていること**
- **2回実行したとき、渡されるURLのクエリ値が異なること**
  （同じURLだとブラウザが再読み込みしない恐れがあるため、退行検知として重要）

### エラー

- 変換結果が空のときエラー終了すること
