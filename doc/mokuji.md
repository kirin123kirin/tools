# mokuji コマンド設計書

## 概要

現在アクティブなPowerPointプレゼンテーションの全スライドからタイトルを
抽出し、一覧としてクリップボードにコピーする `tools mokuji` サブコマンド。

解決したい問題:

- 目次スライドを手作業で作るには、全スライドを1枚ずつ開いてタイトルを
  書き写す必要がある。スライド数が多いと単純に手間で、構成変更のたびに
  作り直しも発生する
- タイトルは必ずしも正規の「タイトルプレースホルダー」に入っているとは
  限らない（SVGから図形化した後の手動配置や、レイアウトを崩して
  自由配置したスライドなど）ため、プレースホルダーの中身だけを見ると
  空欄を拾ってしまう

サブコマンド名・単体エントリーポイント名ともに `mokuji`
（`pyproject.toml` の `[project.scripts]` に `mokuji = "tools.cli:run_as_subcommand"` を追加）。

## `outline` との関係

`outline.md` で「目次生成は別コマンドとして切り離す」とした、その別コマンドが本コマンド。

| コマンド | 役割 | 方向 |
| --- | --- | --- |
| `outline` | クリップボードのテキスト → PowerPointにスライドを追加 | テキスト → スライド |
| `mokuji` | PowerPointの全スライドタイトル → クリップボードへ一覧出力 | スライド → テキスト |

`outline`が生成した目次スライドのタイトル一覧を作り直したい場合にも、
本コマンドをそのまま使える（`outline`側が目次を持たないぶん、
構成を変えるたびに`mokuji`で一覧を取り直す運用になる）。

## 対象

**アクティブなPowerPointプレゼンテーションの全スライド**。範囲指定
（選択スライドのみ等）は持たない。`ikko`と異なり、「一覧を作る」という
性質上、部分適用の需要が薄いため単純さを優先する。

- PowerPoint COM接続の取得は `ikko`/`outline` と共通の
  `common/powerpoint.py` の `get_running_powerpoint()` /
  `get_active_presentation()` を使う（関数シグネチャ・例外の契約は
  `ikko.md` の「他コマンドとの関係」節を正本とする）
- **PowerPointが起動していない、またはプレゼンテーションが開かれていない場合は
  エラー終了する。** `outline`と異なり新規起動はしない
  （一覧化する対象が存在しないのに起動する意味がないため。`ikko`と同じ判断）。
  `get_running_powerpoint()` の `PowerPointNotRunningError`、
  `get_active_presentation()` の `NoActivePresentationError` を
  そのままエラーメッセージに変換して終了する

## タイトル抽出ロジック

各スライドについて、以下の優先順位で判定する。

1. **`Slide.Shapes.HasTitle`が真、かつタイトルプレースホルダーの
   テキストが空でない場合**: `Shapes.Title.TextFrame.TextRange.Text` を使う
2. **上記が使えない場合**（`HasTitle`が偽、または`HasTitle`は真だが
   テキストが空）: スライド内のテキストを持つシェイプのうち、
   **`Top`座標が最も小さい（一番上にある）シェイプのテキスト**を代用する
3. 代用も含めてテキストが1つも見つからない場合、**空文字列**として扱う

### `HasTitle` は「プレースホルダーの枠の有無」であり「文字の有無」ではない

実機検証で確認した重要な事実: **`Shapes.HasTitle`はタイトルプレースホルダーという
枠が存在するかどうかを示すだけで、その中身が空文字列でも`True`
（`-1`）を返す。** レイアウトに「タイトル」枠があれば、利用者が何も
入力していなくても`HasTitle`は真になる。

したがって「プレースホルダーにタイトルが入力されているか」の判定には
`HasTitle`だけでは不十分で、**`HasTitle`が真の場合でも
`Shapes.Title.TextFrame.TextRange.Text` の中身が空文字列かどうかを
別途確認する**必要がある。空文字列なら手順2（代用）に進む。

また、`HasTitle`が偽のスライド（白紙レイアウト等）で`Shapes.Title`に
アクセスすると実行時エラーになるため、**`HasTitle`を確認してから
`Shapes.Title`にアクセスする**（先にチェックせず`Title`へ直接アクセスしない）。

### 代用対象から除外するシェイプ

`Top`最小のシェイプを探す際、以下は候補から除外する:

- テキストフレームを持たないシェイプ（画像、線、図形装飾など）
- テキストが空、または空白のみのシェイプ

### タイトルが1つも見つからないスライドの扱い

**空文字列として一覧に含める。** 該当スライドをスキップせず、
スライド番号と一覧の対応関係を保つ（区切りスライドや白紙スライドが
あっても、一覧のN行目が常にN枚目のスライドに対応するようにする）。

## 出力

**タイトルのみを1行1件で列挙し、クリップボードにコピーする（番号は付けない）。**

```text
第1章 導入
背景と課題
提案手法
（このスライドは空文字列だった場合、この行も空行として出力される）
まとめ
```

### 改行の処理順序

以下の順で処理する（順序を誤ると、タイトル内改行が行区切りの改行と
区別できなくなるため、この順序を厳守する）。

1. **各タイトル文字列内の改行（`\r`/`\n`/`\r\n`のいずれでも）を
   半角スペースに変換し、1つのタイトルが必ず1行に収まる状態にする**
   （COMから取得した`TextRange.Text`はスライド上の改行が`\r`で
   返るため、`\r`・`\n`・`\r\n`のすべてを変換対象にする）
2. 1行に収まったタイトルを `"\n"` で連結し、一覧全体を1つの文字列にする
   （この時点での改行は「タイトル同士の区切り」のみを意味する）
3. **最後に一覧全体をCRLFへ統一**する（`vv`/`outline`と同じ方針、
   `common/textfile.py` の `to_crlf()` を利用）
4. クリップボードへの書き込みは `CF_UNICODETEXT` のみ
   （`common/clipboard.py` の `copy_text_to_clipboard()` を再利用）

完了後、標準出力に「N件のタイトルをコピーしました」のように
件数を含めた1行の完了メッセージを表示する（結果一覧そのものは
標準出力に出さない。`vv`の完了メッセージと同じ方針）。

## エラー処理

- PowerPointが起動していない場合: 「PowerPointでプレゼンテーションを
  開いた状態で実行してください」と表示してエラー終了する
- プレゼンテーションが開かれていない場合: 同様にエラー終了する
- スライドが0枚のプレゼンテーションの場合: エラーにはせず、
  「対象のスライドがありません」と表示して正常終了する
  （クリップボードへの書き込みは行わない）
- COM操作中に例外が発生した場合: 例外内容を含めたエラーメッセージで終了する
  （本コマンドは読み取り専用の処理のため、`ikko`と異なりUndoに関する
  注意書きは不要）

## セキュリティ方針との整合（CLAUDE.md）

- **COM操作は`pywin32`の公開APIのみ**を使う（`ikko`/`outline`と同じ）
- 本コマンドは**読み取り専用**（PowerPoint側の内容を一切変更しない）。
  `StartNewUndoEntry()`等のUndo対策は不要
- キー入力の自動送信・グローバルキーフックは行わない
- 常駐・バックグラウンド監視をしない。実行のたびに1回だけ全スライドを読み、
  クリップボードへ書き込んで終了する
- 外部通信は発生しない
- 何枚のスライドから、何件のタイトルを抽出したかを `common/logging.py`
  経由でログに出す

## テスト方針

タイトル抽出ロジックはCOM非依存の形にはしづらい
（`Shapes.HasTitle`・`Shapes.Title`・シェイプの`Top`座標といった
COMオブジェクトの構造に直接依存するため）。`tests/processing/test_mokuji.py`
でCOMオブジェクトを `MagicMock` によりモックしてテストする。

### タイトル抽出の優先順位

- `HasTitle`が真で、タイトルプレースホルダーにテキストがあれば
  それが使われること
- **`HasTitle`が真だが、タイトルプレースホルダーのテキストが空文字列**の場合、
  `Top`最小のシェイプのテキストが代用されること（退行検知として重要:
  `HasTitle`だけで判定を打ち切ると本来拾うべき手動タイトルを逃すため）
- `HasTitle`が偽の場合、`Shapes.Title`に一切アクセスせず
  `Top`最小のシェイプのテキストを使うこと（`HasTitle`偽で`Title`に
  アクセスするとCOM例外になるため、アクセスしないこと自体を検証する）
- `Top`最小のシェイプが複数の候補から正しく選ばれること
  （候補のシェイプ順がバラバラでも、常に最小Topのものが選ばれること）
- 代用候補からテキストフレームを持たないシェイプが除外されること
- 代用候補から空文字列・空白のみのシェイプが除外されること
- 上記いずれの手段でもタイトルが見つからない場合、空文字列になること
  （例外にならないこと）

### 一覧の対応関係

- スライドが複数あり、一部がタイトルなし（空文字列）でも、
  一覧の行数がスライド数と一致すること（該当スライドがスキップされず、
  空行として出力されること）
- タイトルに改行が含まれる場合、半角スペースに変換され1行に収まること

### 出力のテスト

- クリップボードに`CF_UNICODETEXT`のみがセットされ、番号や装飾を含まない
  タイトルのみの一覧になること
- 改行がCRLFで統一されてクリップボードに入ること
- 完了メッセージに件数が含まれ、一覧本体は標準出力に出ないこと

### エラー処理のテスト

- PowerPointが起動していない場合、新規起動を試みずエラー終了すること
- プレゼンテーションが開かれていない場合にエラー終了すること
- スライドが0枚の場合、エラーではなく正常終了し、
  クリップボードへの書き込みが発生しないこと
- COM例外時に、例外内容を含むエラーメッセージで終了すること
