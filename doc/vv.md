# vv コマンド設計書

## 概要

定型プロンプト（長文テンプレート）をクリップボードに即座にコピーする `tools vv` サブコマンド。

解決したい問題:

- 決まった長文プロンプトを使いたいだけなのに、フォルダを開く→ファイルを探す→開く→
  全選択してコピーする→閉じる、という手間がかかる
- 対話型の変数穴埋めや複雑な管理システムは不要。ただの定型文がサクッと入ればよい

理想の動作: キーを一発叩くか、番号を少し選ぶだけで、目の前の入力欄に
Ctrl+Vでドンと貼り付けられる状態になること。

サブコマンド名・単体エントリーポイント名ともに `vv`
（`pyproject.toml` の `[project.scripts]` に `vv = "tools.cli:run_as_subcommand"` を追加）。
短く叩きやすい名前を優先し、他コマンドのような対象物由来の命名はしていない。

## 貼り付けの範囲

**クリップボードにテキストをコピーするところまでを行う。実際の貼り付け（Ctrl+V）は
利用者自身が行う。**

- キー入力の自動送信（`SendInput`等）は行わない。CLAUDE.mdの「標準・公開APIのみを使う」
  「挙動が透明なツールとして作る」という方針に沿い、キーロガー的に誤認されうる
  グローバルなキー送信機構には踏み込まない。
- 結果として利用者の操作は「`vv <番号>` を叩く → Ctrl+V を押す」の2ステップになる。

## プロンプトの保存場所

`%APPDATA%\tools\vv\` フォルダ配下に、**1ファイル1プロンプトの `.txt` ファイル**として置く。

- 既存の `common/config.py` の `default_config_path()`
  （`%APPDATA%\tools\config.toml`）と同じ置き場所の流儀に揃え、
  `common/config.py` に `vv_prompts_dir() -> Path`（`%APPDATA%\tools\vv\`）を追加する。
- ファイル名がそのままプロンプト名として一覧に表示される（拡張子 `.txt` は表示上省く）。
- フォルダが存在しない場合は空の一覧として扱う（自動作成はしない。
  最初の1つは利用者が手で置く）。
- サブフォルダは走査しない（フォルダ直下の `.txt` のみを対象とする、単純さを優先）。

### 対象ファイルの選び方と並び順

- **拡張子の大小文字は区別しない。** `.txt` / `.TXT` / `.Txt` のいずれも対象にする
  （Windowsのファイルシステムは大小を区別せず、`Path.glob("*.txt")` の挙動も
  環境に依存しうるため、`name.lower().endswith(".txt")` で明示的に判定する）。
- **`Path.glob()` の戻り順に依存せず、明示的に `sorted()` する。**
  globの列挙順はOS・ファイルシステム依存で保証がないため。
- 並び順は**ファイル名のUnicodeコードポイント順**（`sorted()` の既定）とする。
  - **日本語名は五十音順にはならない。** 半角英数が先に並び、その後に日本語が続く
    （例: `01_よく使う` → `AI依頼` → `zzz` → `企画書` → `謝罪メール`）。
  - 意図した順に並べたい場合は、ファイル名の先頭に `01_` のような
    接頭辞を付ける運用で対応する。読みがな順に並べる機能は持たない
    （そのためだけに読み仮名の管理を持ち込むのは、このツールの単純さに見合わない）。

### エンコーディング

**UTF-8(`utf-8-sig`) → CP932 のフォールバック**で読む
（メモ帳等で作成されたファイルも読めるようにするため）。これは `cwc` と同じ方針。

既存の `common/clipboard.py` に同じロジックの `_read_text_file()` があるが、
**そのままは再利用しない**。理由は2つ:

- プライベート関数（`_` 接頭辞）であり、モジュール外からの利用を想定していない
- 失敗時に `ClipboardTextError` を投げるが、`vv` のファイル読み込み失敗は
  クリップボードとは無関係であり、例外の意味がずれる

`common/textfile.py` のような新しいモジュールに
`read_text_with_fallback(path: Path) -> str` として切り出し、
`clipboard.py` 側の `_read_text_file()` もそれを呼ぶ形に寄せる
（`clipmd`/`clipview` で `markdown_html.py` を切り出したのと同じ判断）。

### 改行コード

**クリップボードに書き込む直前に CRLF へ統一する。**

- Windowsのクリップボードテキストの慣習はCRLFであり、メモ帳など
  LFを解釈しないアプリに貼ると改行が失われる恐れがあるため。
- クリップボードAPI自体は改行コードを変換せず、**書き込んだ通りに保持する**
  （LFで書けばLFのまま貼り付けられることを検証済み）。したがって
  ツール側で明示的に統一する必要がある。
- 実装は「読み込み後に一度LFへ正規化 → 書き込み直前にCRLFへ変換」の2段とする
  （元ファイルがCRLF/LF/CRのいずれでも、また混在していても同じ結果になる）。
- 既存の `common/clipboard.py` の `_normalize_newlines()`（LFへ統一）が
  前段に使えるが、こちらも上記と同じ理由で公開関数として切り出すか、
  `vv` 側に持つかを実装時に揃える。

## 一覧・選択の挙動

### 引数なしで実行した場合: 常に一覧を表示するだけ

```text
> vv
  1: 企画書雛形                以下の要件で企画書のドラフトを作成してください。
  2: 謝罪メール                下記の状況について、取引先向けの謝罪メールを作成し...
  3: 定例議事録テンプレート    次の議事メモを整形し、決定事項とToDoを抽出してくだ...
 ...
 12: レビュー依頼             添付のコードについて、以下の観点でレビューしてくだ...
```

- **クリップボードには何もコピーしない。** 表示するだけで副作用を持たない。
- 一覧はファイル名の**昇順**で並べ、番号は表示のたびに1から振り直す
  （固定IDを永続化する仕組みは持たない。単純さを優先する設計方針のため）。
- 最頻用のプロンプトを若い番号にしたい場合は、ファイル名の先頭に
  `01_` のような接頭辞を付ける運用で対応する（ツール側では特別扱いしない）。

#### 表示の体裁

- **番号は右寄せ**にする。数十個を想定しており2桁になるため、
  1桁と2桁が混在しても列が揃うようにする。
- **プロンプト名の後に本文の冒頭を短く添える。** ファイル名だけでは
  中身を思い出せない場合に、開かずに判別できるようにするため。
  - 本文の**最初の非空行**を使う（先頭が空行のファイルでも意味のある行が出るように）
  - 一定の表示幅を超える分は末尾を `...` で切り詰める
  - 本文が空のファイルは名前だけを表示する
- プロンプト名の列幅は一覧内で最も長い名前に合わせて揃える
  （名前の長さがまちまちでもプレビューの開始位置が揃う）。

##### 桁揃えは「文字数」ではなく「表示幅」で行う

**`len()` による文字数ではなく、全角を2・半角を1として数えた表示幅で揃える。**
日本語のプロンプト名では両者が一致しないため、文字数で揃えると列が崩れる（検証済み）。

```text
len()で揃えた場合:
  1: 企画書雛形        ← プレビュー開始位置
  2: AI_prompt    ← プレビュー開始位置      ← 半角名だけ手前にずれる
  3: 定例議事録テンプレート  ← プレビュー開始位置
```

- 判定は `unicodedata.east_asian_width(c) in "WF"` で全角とみなす方式を使う
  （`clipfmt` のテストで表の桁揃えを検証する際に用いているのと同じ考え方）。
- **プレビューの切り詰めも同じく表示幅で行う。** 文字数で切ると、
  全角の多い行だけが横に長くなり、右端が揃わない。
- 表示幅を計算するヘルパーは複数箇所で必要になるため、
  `common/` 配下に `display_width(s: str) -> int` として置く。

### 番号を引数で指定した場合: 即座にコピーして終了

```text
> vv 3
```

- 該当する番号のプロンプト本文をクリップボードにコピーし、即終了する。
- **一覧は表示しない。** 「キーをポンと叩くだけ」を実現するための経路であり、
  余計な出力は最小限にする。
- コピーが完了した旨とプロンプト名を短く1行だけ表示する（例: `コピーしました: 企画書雛形`）。
- 存在しない番号を指定した場合は、一覧の範囲を示したエラーメッセージで終了する
  （例: `番号は 1〜12 の範囲で指定してください`）。

## クリップボードへの書き込み

`CF_UNICODETEXT` のみをセットする（`common/clipboard.py` の `copy_text_to_clipboard()` を再利用）。
`CF_HTML` は関与しない。プレーンテキストとして貼り付けられることが目的であり、
装飾を伴うリッチテキスト化は不要。

## エラー処理

- プロンプトフォルダが存在しない、または中に `.txt` が1つもない場合:
  「プロンプトが登録されていません。`%APPDATA%\tools\vv\` に .txt を置いてください」
  と表示してエラー終了する（`vv`・`vv <番号>` どちらでも同じ扱い）。
- **番号が範囲外の場合**: `0` や負数も含めて、有効範囲を示す同じエラーで終了する
  （例: `番号は 1〜12 の範囲で指定してください`）。1始まりであることが
  メッセージから分かるようにする。
- **番号が数値でない場合**（`abc` / `1.5` / 空文字など）: 数値を期待している旨を
  示してエラー終了する。argparseの `type=int` に任せると
  エラーメッセージが英語になるため、自前で検証してメッセージを出す。
- ファイルの読み込みに失敗した場合（アクセス権限等）: そのファイル名を含めたエラーにする。
- **`%APPDATA%` が定義されていない場合**: `os.environ["APPDATA"]` は `KeyError` を
  投げるため、その旨を明示したエラーメッセージで終了する
  （Windows専用ツールなので通常は起こらないが、`KeyError` がそのまま
  トレースバックとして出るのは避ける）。

## セキュリティ方針との整合（CLAUDE.md）

- クリップボードへの書き込みは `win32clipboard` の公開API経由（既存の
  `copy_text_to_clipboard()` を再利用）のみ。キー入力の送信・グローバルフックは行わない。
- 実行のたびに1回だけフォルダを読み、その場で終了する。常駐・バックグラウンド監視はしない。
- 外部通信は発生しない（すべてローカルファイルの読み込みとクリップボード書き込みのみ）。
- 何を読み込み、何をコピーしたかを `common/logging.py` 経由でログに出す。

## 他コマンドとの関係

`clip*` 系コマンド（`clipmd`/`mdtsv`/`clipview`/`clipfmt`）はクリップボードの**中身を変換する**
ことが役割だが、`vv` はクリップボードに**定型文を投入する入り口**という別の役割を持つ。
変換の対象にはならない一方向の供給源である。

## テスト方針

`tests/processing/test_vv.py` に以下を用意する。
クリップボードAPI・ファイルシステムは `monkeypatch`／`tmp_path` でモックする。

### 一覧表示

- 引数なし実行で `.txt` ファイル名の昇順に番号付き一覧が表示されること
- 引数なし実行ではクリップボードへの書き込みが一切発生しないこと
- 拡張子 `.txt` が表示上省かれること
- フォルダが存在しない場合、その旨のエラーメッセージで終了すること
- フォルダはあるが `.txt` が1つもない場合も同様にエラー終了すること
- **番号が右寄せで揃うこと**（1桁と2桁が混在する10件以上のケースで検証する）
- **各行に本文の冒頭プレビューが添えられること**
- 先頭が空行のファイルで、**最初の非空行**がプレビューに使われること
- 本文が空のファイルは名前だけが表示され、エラーにならないこと
- 長い本文のプレビューが `...` で切り詰められること

### 桁揃え（表示幅）

- **全角名と半角名が混在してもプレビューの開始位置が揃うこと**
  （`企画書雛形` と `AI_prompt` を並べ、表示幅で計算されていることを検証する。
  `len()` 実装だと崩れるため、退行検知として重要）
- 切り詰めが文字数ではなく**表示幅**で行われること
  （全角のみの行と半角のみの行で、切り詰め後の表示幅がほぼ揃うこと）

### 対象ファイルと並び順

- `.TXT` / `.Txt` など**大文字を含む拡張子も対象に含まれること**
- `.md` など `.txt` 以外の拡張子は対象外であること
- **`Path.glob()` の列挙順に関わらず、常にファイル名順で並ぶこと**
  （globが逆順を返すようモックしても、出力は昇順であることを検証する）

### 番号指定

- 有効な番号を指定すると、該当ファイルの内容がクリップボードにコピーされること
- 番号指定時は一覧が表示されないこと
- コピー後にプロンプト名を含む短いメッセージが1行表示されること
- **境界値**: 最初(`1`)と最後(件数と同じ番号)が正しくコピーできること
- **`0` / 負数 / 件数+1 のいずれもエラー終了すること**（有効範囲がメッセージに含まれること）
- 数値でない引数（`abc` / `1.5` / 空文字）でエラー終了し、
  英語のargparse既定メッセージではなく日本語のメッセージが出ること

### ファイル読み込み

- UTF-8（BOM付き/なし）のファイルが読めること
- CP932のファイルがフォールバックで読めること
- サブフォルダ内の `.txt` は一覧に含まれないこと
- **`%APPDATA%` が未定義の場合、`KeyError` のトレースバックではなく
  日本語のエラーメッセージで終了すること**

### 改行コードのテスト

- **LF改行のファイルをコピーすると、クリップボードにはCRLFで入ること**
- CRLF改行のファイルでも、CRLFのまま（`\r\r\n` に増えたりしないこと）
- CR単独やCRLF/LF混在のファイルでも、すべてCRLFに統一されること

### 出力

- クリップボードに `CF_UNICODETEXT` のみがセットされ、`CF_HTML` はセットされないこと
