# cwc コマンド設計書

## 概要

入力テキストから頻出語を抽出し、ワードクラウド画像を生成する `tools cwc` サブコマンド。
`touka` / `denoise` / `kukiri` と同じ入出力規約に従う。

サブコマンド名・単体エントリーポイント名ともに `cwc`
（`pyproject.toml` の `[project.scripts]` に `cwc = "tools.cli:run_as_subcommand"` を追加し、
`cwc.exe` として単体でも実行可能にする）。

## 入力

位置引数 `path`（省略可）でテキストファイルパスを受け取る。

- `path` 指定あり: そのテキストファイルを読み込む
- `path` 省略時: クリップボードのテキストを使用

### エンコーディング

国内のWindows環境ではCP932(Shift_JIS)のテキストファイルが日常的に存在するため、
UTF-8決め打ちにはしない。

- 既定は**UTF-8 → CP932 の順に試すフォールバック**とする。
  UTF-8で `UnicodeDecodeError` になった場合にCP932で読み直す
  （逆順にすると、CP932として解釈可能なバイト列を化けたまま読んでしまうため、UTF-8を先に試す）。
- BOM付きUTF-8も読めるよう、UTF-8の試行には `utf-8-sig` を使う
  （BOMなしのファイルでも問題なく読める）。
- `--encoding` オプションで明示指定できるようにする。
  指定時はフォールバックせず、そのエンコーディングで読めなければエラー終了する。
- どのエンコーディングで読んだかを `common/logging.py` 経由でログに出す
  （文字化けが疑われるときの切り分け材料になるため）。
- クリップボードからのテキスト取得（`CF_UNICODETEXT`）は
  Windows APIの時点でUTF-16のため、この問題は発生しない。

### 改行コード

CRLF / LF / CR が混在しうるため、読み込み直後に**LFへ統一**する（`\r\n` → `\n`、残った `\r` → `\n`）。

- 統一しないと、区切り文字の文字クラスや文分割の正規表現で `\r` が語末に残り、
  `単語\r` と `単語` が別語として集計されてしまう。
- ファイル読み込みはPythonのユニバーサル改行（既定）で概ね吸収されるが、
  クリップボード由来のテキストは変換されないため、経路を問わず明示的に統一する。

画像系コマンドの `load_image()` はPillow画像専用のため流用できない。
`common/clipboard.py` に対となる `load_text(path: str | Path | None) -> LoadedText` を新設する。

```python
@dataclass(frozen=True)
class LoadedText:
    text: str
    source_path: Path | None
    source_kind: SourceKind
```

`source_kind` は画像系と共通の `SourceKind`（`common/clipboard.py` の Literal）を使う。
`LoadedText` 専用に狭めた Literal を宣言すると、後述の `HasSource` プロトコル
（書き換え可能な属性は不変）を満たせず mypy strict が通らないため、型は共通のものに揃える。

- `path` 指定時は `source_kind="path"`、`source_path` にそのパスを入れる。
- クリップボードに「ファイルオブジェクト」がコピーされている場合（Explorerでテキストファイルをコピー）は、
  そのファイルを読み込み **`source_kind="clipboard_file"`** とする（画像系と同じ値）。
  出力先が「元ファイルの隣」ではなく「`%TEMP%` + クリップボードへコピー」になるため、
  `"path"` と区別する必要がある。
- クリップボードにプレーンテキストが入っている場合は `source_kind="clipboard_text"`、`source_path=None`。
- 取得は `win32clipboard` の `CF_UNICODETEXT` / `CF_HDROP` を読む形になる
  （Pillow `ImageGrab` はテキストを扱わないため、ここは新規の薄いラッパーが必要）。

## 単語分割・前処理

処理の流れは以下の順。

1. **正規化**（分割前の前処理、常時適用）
2. 以降は2系統に分かれる
   - **語単位**（既定）: 分割（既定は区切り文字、`-w` で分かち書き）
     → 品詞での絞り込み（`--hinshi` 時）→ 同義語の寄せ（`--semantic` 時）
     → ストップワード除去
   - **文単位**（`--similar` 時）: 文へ分割 → 埋め込みベクトル化 → 類似度クラスタリング
3. 頻度集計 → 描画

オプションの排他関係（いずれも同時指定はエラー）:

- `--similar` × `--semantic` / `-w` / `--hinshi`
  — `--similar` は語ではなく**文**を集計単位にするため噛み合わない
- `--semantic` × `-w` / `--hinshi`
  — 同義語辞書は複合語を含むため、分かち書きすると辞書引きがヒットしない（後述）

`--hinshi` は品詞情報を要するため `-w` を自動的に有効化する。
したがって「既定の区切り文字分割 + `--semantic`」「`-w`/`--hinshi`」「`--similar`」の3系統は互いに独立する。

### 0. 正規化（分割前の前処理）

分割にかける前に、入力テキスト全体へ以下を適用する。表記ゆれを機械的に吸収し、
後段の同義語辞書のエントリ数を減らすのが目的。

- **NFKC正規化**（`unicodedata.normalize("NFKC", text)`）
  - 全角英数 → 半角、半角カナ → 全角カナ、互換文字の統一
- **かな/漢字の表記ゆれ寄せ**
  - 送り仮名・漢字かな交ぜ書きのゆれをルールで統一する（例: `無し` → `なし`、`有る` → `ある`）
  - ルールは辞書ファイルではなくモジュール定数の変換表として持つ（件数が限られるため）

この正規化は**常時適用**とする（`--semantic` / `--similar` の有無に関わらず効く）。
分割前に行うため、区切り文字分割・分かち書き・文分割のいずれの経路でも同じ効果が得られる。
`--similar` の埋め込みベクトル化も、正規化済みの文に対して行う。

### 1. 区切り文字による分割（デフォルト）

入力テキストを以下の**区切り文字の連続**で区切り、得られたトークンをそのまま単語として集計する。

| 種別 | 文字 |
|---|---|
| 空白類 | 半角スペース、全角スペース `　`、タブ、改行（CR/LF） |
| 句点 | `。` |
| かっこ | `（` `）` `「` `」` `『` `』` `【` `】` `〔` `〕` `［` `］` `｛` `｝` `〈` `〉` `《` `》` `(` `)` `[` `]` `{` `}` |

実装は上記を文字クラスにまとめた正規表現で `re.split(r"[...]+", text)` とする。

読点 `、` や感嘆符・疑問符などの約物は**区切りに含めない**（指示により句点とかっこに限定）。
必要になれば後から区切り文字を追加できるよう、文字クラスはモジュール定数として切り出しておく。

- 分かち書き（形態素解析）を行わないため高速で、依存も増えない。
- 英文や、あらかじめ単語区切りされたテキスト（ログ、CSVの1カラム、タグ列など）に適する。
- 分割後の空文字トークンは捨てる。

### 2. 分かち書き（オプション）

`--wakachi` / `-w` 指定時のみ **Janome** による形態素解析で分かち書きして分割する
（純Python実装、外部Cライブラリ・辞書の事前インストール不要）。

- 分かち書きされていない日本語文章を入力する場合に使う。
- 既定では品詞で絞り込まず、分割された全単語（表層形）を集計対象とする。
  絞り込みたい場合は後述の `--hinshi` を使う。
- 依存追加: `pyproject.toml` の `dependencies` に `janome` を追加。
  デフォルト経路では読み込まないため、`import janome` はこのオプションが指定されたときだけ
  行う（遅延インポート）ことで、通常実行時の起動コストを避ける。

#### 品詞による絞り込み（`--hinshi`）

`--hinshi` で、集計対象とする品詞を指定できる。**複数指定可**。

```powershell
cwc memo.txt --hinshi 名詞 動詞
cwc memo.txt --hinshi 名詞,形容詞     # カンマ区切りでも可
```

- argparse では `nargs="+"` で受け、加えて各値のカンマ区切りも展開する
  （`--hinshi 名詞,動詞` と `--hinshi 名詞 動詞` の双方を受け付ける）。
- 指定できるのは Janome（ipadic）の**品詞大分類**の名称:
  `名詞` `動詞` `形容詞` `副詞` `助詞` `助動詞` `連体詞` `接続詞` `感動詞` `接頭詞` `記号` `フィラー` `その他`
- 判定は Janome の `token.part_of_speech` の第1要素（大分類）と突き合わせる。
- 未知の品詞名が渡された場合は、指定可能な一覧を添えたエラーで終了する
  （黙って無視すると、絞り込みが効かない理由が分からなくなるため）。
- 既定（`--hinshi` 未指定）は絞り込みなし = 全品詞。

##### 分かち書きの自動有効化

品詞情報は形態素解析を通さないと得られないため、**`--hinshi` 指定時は `-w` を自動的に有効化する**
（`-w` の明示指定は不要）。既定の区切り文字分割では品詞が取れないため、この扱いとする。

自動で分割方式が変わることになるので、その旨を `common/logging.py` 経由でログに出す。

##### 集計対象の語形

品詞で絞り込む場合、活用形が分散すると頻度が割れてしまう
（例: `使う` / `使っ` / `使い` が別語として数えられる）。
そのため **`--hinshi` 指定時は表層形ではなく基本形（`token.base_form`）を集計対象**とする。
基本形が取れない語（`*` が入る場合）は表層形にフォールバックする。

集計語形が表層形と基本形で切り替わるが、同義語辞書（表層形で記述）とは
`--semantic` × `--hinshi` が排他のため衝突しない。

`--similar` とも排他（文単位の集計では品詞の絞り込みが意味を持たないため、同時指定はエラー）。

#### ユーザー辞書

固有名詞や社内用語が意図せず分割されるのを防ぐため、Janomeのユーザー辞書に対応する
（`Tokenizer(udic=..., udic_type=...)`）。分かち書き経路でのみ効くため、`-w` 未指定時は無視する。

辞書の解決順は以下の3段階で、**下にあるものが上を上書きする**。

1. 同梱の既定辞書 `data/user.dic`
2. 設定ファイル `%APPDATA%\tools\config.toml` の `[cwc] user_dict`
3. コマンドライン `--user-dict`

##### 1. 既定のユーザー辞書（同梱）

- パッケージ内の `data/user.dic` を既定のユーザー辞書として同梱する
  （実体は `src/tools/data/user.dic`。パッケージデータとして配布物に含めるため、
  `pyproject.toml` に `[tool.setuptools.package-data]` の設定を追加する）。
- **中身はJanomeのsimpledic形式（表層形,品詞,読み）に確定した。**
  `.dic` という拡張子だが中身はCSVである点が紛らわしいため、
  先頭にコメント行で形式を明記している。実機検証で
  `Tokenizer(udic=str(path), udic_type="simpledic")` が同梱の
  `data/user.dic` を正しく読み込み、分かち書きできることを確認済み
  （拡張子`.dic`のままで問題なく動作し、`.csv`への改名は不要だった）。
- **`user_dict_type`のようなipadic/simpledicの切り替えオプションは設けない。**
  `_split_wakachi()`は常に`udic_type="simpledic"`で呼び出す。
  同梱辞書自体がsimpledic形式であり、利用者が追記する運用（固有名詞・
  社内用語の追加）もsimpledic形式（表層形,品詞,読みの3列）で足りるため、
  ipadic形式への対応は複雑さに見合わないと判断した
- 初期状態では空、またはサンプル数行のみとし、利用者が追記して育てる想定。
- 同梱辞書が存在しない場合の扱いは後述の「辞書が見つからない場合」に従う
  （配布形態によっては欠落しうる）。

##### 2. 設定ファイルによる上書き

- 設定ファイルの既定位置は `%APPDATA%\tools\config.toml`
  （`common/config.py` には現状「既定位置を決める仕組み」がないため、
  `default_config_path()` のような関数を追加する）。
- 記述例:

  ```toml
  [cwc]
  user_dict = "C:/Users/xxx/dict/mydict.csv"
  ```

  （辞書形式は前述の通りsimpledic固定のため、設定ファイル側に
  形式を指定する項目は持たない。`user_dict`で指定するファイルも
  simpledic形式で用意する）

- 設定ファイルが存在しない場合、`[cwc]` セクションがない場合は、
  同梱の既定辞書をそのまま使う（エラーにしない）。

##### 3. コマンドラインによる上書き

- `--user-dict` 指定時は、同梱辞書・設定ファイルの値の双方を上書きする
  （単発で別の辞書を試せるようにするため）。
- `--no-user-dict` で、同梱辞書も含めて一切のユーザー辞書を無効化できるようにする。

##### 辞書が見つからない場合

同梱辞書・設定ファイル記載・`--user-dict` のいずれの経路でも、
**辞書ファイルが見つからなければその辞書をスキップして処理を続行する**（エラー終了しない）。

ただし黙って挙動が変わると原因が追えなくなるため、
`common/logging.py` 経由で「どのパスの辞書が見つからずスキップしたか」を警告ログに出す。

### 同義語の寄せ（`--semantic`）

`--semantic` 指定時のみ、**意味が同じ語を代表語にまとめて集計する**。
語形がバラバラで意味だけが同じもの（下例）は正規化ルールでは寄せられないため、同義語辞書で対応する。

```text
特になし / 特にない / なし / ない  → 「なし」
```

（`特に無し` `無し` のような漢字表記は前段の正規化で `なし` 系に寄るため、
辞書には正規化後の表記だけを書けばよい。）

- 辞書ファイルは同梱の `data/synonym.tsv`（実体は `src/tools/data/synonym.tsv`）。
  ユーザー辞書と同じくパッケージデータとして配布物に含める。
- 形式はTSV。1行1グループで、**先頭カラムが代表語、以降が異表記**とする。
  行頭 `#` はコメント。

  ```tsv
  # 代表語	異表記1	異表記2	...
  なし	特になし	特にない	ない
  ```

- 寄せは分割後のトークン単位で、異表記 → 代表語の単純な辞書引き置換で行う。
  このオプションでは埋め込みベクトルや類似度計算は使わない
  （決定的で、結果の理由が説明できることを優先）。
  推論ベースで寄せたい場合は後述の `--similar` を使う。
- **前提: 区切り文字分割は「区切り文字が現れるまで」を1トークンとするため、
  `--semantic` が実質的に効くのは、辞書の異表記がそのまま1トークンとして現れる入力に限られる。**
  例えばアンケート回答のように「1行1回答」「CSVの1カラム」など、
  あらかじめ短く区切られたテキストでは機能するが、
  `回答は特になしです` のような文中に埋め込まれた表現は1トークンとして扱われ、ヒットしない。
  文中の表現もまとめて寄せたい場合は `--similar` を使う。
- 前段の正規化が済んだ状態で引くため、辞書には正規化後の表記を書く。
- **`-w`（分かち書き）とは排他**とする。
  辞書には `特になし` のような複合語を書くが、分かち書きすると `特に` / `なし` に分割されるため、
  トークン単位の辞書引きでは永久にヒットしない。
  よって `--semantic` は既定の区切り文字分割専用とし、`-w` との同時指定はエラーにする。
  `--hinshi` は `-w` を自動有効化するため、`--hinshi` との併用も同様にエラーとなる。
- 解決順・欠落時の扱いはユーザー辞書と揃える。
  - 同梱 `data/synonym.tsv` → 設定ファイル `[cwc] synonym_dict` → `--synonym-dict` の順に上書き
  - `--no-synonym-dict` で一切の同義語辞書を無効化
  - 辞書が見つからなければスキップして続行し、警告ログを出す
- どの語をどの代表語に寄せたかは、`common/logging.py` 経由でログに出す
  （集計結果が変わった理由を追えるようにするため）。

### 文の類似度クラスタリング（`--similar`）

`--similar` 指定時は、集計単位を**語ではなく文**に切り替え、
埋め込みベクトルの類似度で文をクラスタリングして、クラスタごとの件数を頻度として集計する。

アンケートの自由記述のように「同じ趣旨の回答が表現を変えて多数並ぶ」入力を、
辞書のメンテなしにまとめられるのが狙い。`--semantic` の辞書引きでは拾えない未知の表現にも効く。

#### 処理の流れ

1. 正規化後のテキストを**文に分割**する
   （区切りは句点 `。`、改行、および `!` `?`。**正規化後は全角の`！``？`が半角に変換されるため、
   半角で指定する**。語分割の区切り文字とは別の定数として持つ）
2. 各文を埋め込みベクトルに変換する
3. コサイン距離をもとに**閾値付き凝集型階層クラスタリング**（average linkage）でまとめる
   — numpyによる自前実装（後述）
4. 各クラスタの**代表文**を選び、その文の重みをクラスタの所属件数とする
   - 代表文は「クラスタ内で最も出現回数が多い文」、同数なら「最も短い文」を採る
     （`特になし` と `特に何もありません` が同一クラスタなら短い方が代表になる）
5. 代表文が長すぎる場合は**切り詰める**（後述）
6. 代表文と件数の対から `wordcloud` の `generate_from_frequencies()` で描画する

#### 代表文の文字数上限

ワードクラウドは各要素を1つの文字列として描画するため、長い文はごく小さく描かれて読めなくなる。
そのため代表文には文字数上限を設ける。

- **既定は10文字**。超過分は切り詰め、末尾に省略記号 `…` を付ける。
- `--similar-max-length` オプションで変更できるようにする（`0` で無制限）。
- 切り詰めは**描画直前にのみ**行う。クラスタリングと代表文の選定は元の全文で行うため、
  上限値を変えても文のまとまり方は変わらない（見た目だけが変わる）。
- 切り詰めによって別クラスタの代表文と同一の文字列になった場合は、
  **頻度を合算して1つの表示として扱う**（同じ表示名が2つあると
  `generate_from_frequencies()` の辞書キーが衝突するため、実質的にこの扱いにせざるを得ない）。
  切り詰め後の文字列をキーに集計し直す実装とする。
  切り詰め前は別クラスタだった旨はログに残し、集計結果の見た目と内部のクラスタ数が
  一致しないことがある点を利用者が追えるようにする。

#### 埋め込みモデル

**fastembed も sentence-transformers も使わず、onnxruntime を直接叩いて自前実装する。**

理由: fastembed は `huggingface-hub` / `tokenizers` / `onnx` / `loguru` など多数のパッケージを
引き込むため、既存の `rembg` 環境と依存が衝突するリスクがある
（`sentence-transformers` は torch を引き込むためさらに重い）。
このプロジェクトは `rembg[cpu]` 経由で既に onnxruntime を持っており、
推論そのものは onnxruntime だけで足りる。

構成要素は以下の3つ。

| 要素 | 手段 |
|---|---|
| 推論 | `onnxruntime.InferenceSession` でONNXモデルを直接実行 |
| トークナイズ | `tokenizers` パッケージ（Hugging Faceのtokenizer.jsonを読む。Rust実装で軽量） |
| プーリング・正規化 | numpy で mean pooling + L2正規化を自前実装 |

- `onnxruntime` は `rembg` 経由で入るが、**直接使うため `dependencies` に明示的に宣言する**
  （他パッケージの推移的依存に暗黙に頼るのは壊れやすい）。
- `tokenizers` のみが実質的な新規依存。単体パッケージで依存が少なく、衝突リスクは小さい。

##### モデルの取得

- 多言語対応の小型埋め込みモデル（ONNX形式）を既定とし、
  `--similar-model` でモデルの識別名を差し替えられるようにする。
- **初回実行時に、モデル本体（.onnx）とtokenizer.jsonをダウンロードする。**
  `huggingface-hub` を使わず `urllib` で直接取得するため、
  **URLを設計・コード上に固定値として持つ**（どこへ繋ぐかがコードから一目で分かる形にする）。
- CLAUDE.mdの方針に従い、接続先ホスト（`huggingface.co`）と取得するファイルを
  READMEに明記し、IT部門がプロキシ/EDRのアローリストに登録できるようにする。
- キャッシュ先は `%LOCALAPPDATA%\tools\models\<モデル名>\` とし、READMEに記載する。
  2回目以降はダウンロードしない。
- ダウンロード開始時・完了時にログを出す（何MB取得したかが分かる形にする）。
- ダウンロードに失敗した場合は、接続先URLを含めたエラーメッセージで終了する
  （プロキシ設定の問題を切り分けやすくするため）。

#### クラスタリングの自前実装

`scikit-learn` も依存に加えず、**numpy で average-linkage の凝集型クラスタリングを実装する**。

- L2正規化済みベクトルの内積からコサイン類似度行列を作り、距離行列（`1 - 類似度`）に変換する。
- 最も距離が近いクラスタ対を、`distance_threshold` を超えるまで繰り返し統合する
  （クラスタ間距離は所属要素間距離の平均 = average linkage）。
- クラスタ対を統合するたびに全ペアの平均距離を再計算する素朴な実装は O(n³) になるため、
  **Lance-Williams更新式**で統合後の距離をO(1)更新し、全体をO(n²)に収める
  （`d(k, i∪j) = (|i|·d(k,i) + |j|·d(k,j)) / (|i|+|j|)`）。
  素朴な実装より複雑になるため、数十行では収まらない前提で実装時間を見積もる。
- `sklearn.cluster.AgglomerativeClustering`（`metric="cosine"`, `linkage="average"`）と
  同じ結果になることを確認済み（`tests/common/test_clustering.py` の
  `test_matches_sklearn_on_random_inputs`。`scikit-learn` は
  `dev` の optional-dependencies としてテスト専用に追加している）。
- 距離行列が O(n²) のメモリを使う点は sklearn を使う場合と同じ。

#### オプション

| オプション | 既定 | 内容 |
|---|---|---|
| `--similar` | 無効 | この機能を有効化する |
| `--similar-threshold` | 0.2（コサイン距離） | クラスタをまとめる距離の閾値。小さいほど厳しく、似た文しかまとめない |
| `--similar-model` | 小型多言語モデル | 使用する埋め込みモデル名 |
| `--similar-max-length` | 10 | 代表文の表示文字数の上限（`0`で無制限）。超過分は`…`で切り詰め |

閾値はコサイン**距離**で指定する（類似度0.8 ≒ 距離0.2）。
**既定値は0.2のまま実装で確定した**（実装後の調整は行っていない。
利用者が体感に合わせて`--similar-threshold`で調整する運用とする）。

#### 注意点・制約

- `--semantic` / `-w` / `--hinshi` とは**排他**
  （集計単位が語 vs 文で噛み合わないため、同時指定はエラー）。
- ストップワードは適用しない（文単位のため、語のストップワードは意味を持たない）。
- 文の数が多いと総当たりの類似度計算が重くなる（凝集型は O(n²) のメモリを使う）。
  **入力文数の上限は2000件に確定した**（`_SIMILAR_MAX_SENTENCES = 2000`）。
  超過時は超過した旨を警告ログに出し、先頭2000件のみを対象に処理を続行する
  （エラー終了はしない。O(n²)のメモリ使用量が現実的な範囲に収まる件数として設定）。
- 結果が閾値とモデルに依存し、辞書引きほど説明的でない点は割り切る
  （どの文がどのクラスタにまとまったかはログに出して追えるようにする）。
- 依存追加は `tokenizers` のみ（`onnxruntime` は既にあるが明示宣言する）。
  どちらも `--similar` 指定時のみ使うため、**遅延インポート**にして
  通常実行時の起動コストとインポートエラーの影響を避ける。

### ストップワード

**語単位の経路**（既定の区切り文字分割、`-w` の分かち書き）で、集計前にストップワードで雑音を落とす。
`--similar` の文単位経路では適用しない（語のストップワードは文に対して意味を持たないため）。

- **デフォルトの日本語ストップワードリストをコード内に同梱する**
  （`processing/cwc.py` 内のモジュール定数、あるいは `common/` 配下のデータとして定義）。
  対象は概ね以下:
  - 形式名詞・指示語: 「こと」「もの」「これ」「それ」「あれ」「ため」「よう」「とき」など
  - 汎用動詞・補助的な語: 「する」「ある」「いる」「なる」「できる」など
  - 助詞・助動詞（分かち書き時に単独トークンとして出るもの）: 「の」「に」「は」「を」「が」「で」「と」など
  - 記号・約物・空白のみのトークン、および1文字の記号
- `--stopwords` オプションで、デフォルトリストへ**カンマ区切りの語**を追加できる。
  ファイルで追加したい場合は別途 `--stopwords-file` を使う
  （パスにカンマが含まれるとカンマ区切りと判別できないため、オプションを分ける）。
- `--no-default-stopwords` でデフォルトリストを無効化し、ユーザー指定分のみを使う逃げ道も用意する。
- `wordcloud` 内蔵の英語 `STOPWORDS` も併用する（和文・英文が混じった入力に対応するため）。
  ただし**自前で適用する必要がある**点に注意。
  `wordcloud` が `stopwords` を見るのは `process_text()`（= `generate_from_text()` 経路）だけで、
  本設計が使う `generate_from_frequencies()` は `stopwords` を一切参照しない（1.9.6で確認済み）。
  よって `wordcloud.STOPWORDS` を自前の日本語リストに**合成して、集計前に自分で除去する**。
- `--no-default-stopwords` 指定時は、日本語リストと英語 `STOPWORDS` の双方を無効化する。

## ワードクラウド生成

- 描画ライブラリは **wordcloud**（Pythonデファクト標準）を採用。依存追加: `wordcloud`。
- 日本語の文字化け対策として、`wordcloud` へのフォントパス指定は必須。
  **既定はシステムフォントのメイリオ**（`C:\Windows\Fonts\meiryo.ttc`）を使う。
  Windows 11 標準搭載のため同梱は不要で、リポジトリ・exeが肥大化しない。
- `--font` オプションで任意のフォントファイルパスを指定できるようにする。
- 既定のメイリオが存在しない場合は、その旨を明示したエラーを出して終了する
  （黙って文字化けした画像を出さない）。
- 出力画像はPNG、背景・サイズ・カラーマップ等はひとまずデフォルト値で固定し、
  必要に応じて `--width` / `--height` 等のオプションを追加余地として残す（初期実装では固定でよい）。

### 集計結果が空になった場合

空のテキスト、または全語がストップワードで除去された結果、集計対象が0件になった場合は
**明示的なエラーメッセージを出して終了する**（`wordcloud` に空の頻度辞書を渡すと
`ValueError` になるため、その前に自前で検出する）。

エラー文には「入力が空か、全語がストップワードで除去された可能性」を示し、
`--no-default-stopwords` を試す余地があることが分かるようにする。

## 出力

既存の `common/output.py` の `save_result()` を流用する
（受け取る型は後述の `HasSource` プロトコルに広げる）。

対応表（画像系と同じ規約）:

| 入力パターン | 出力 |
|---|---|
| テキストファイルパス指定 | 元ファイルと同じ場所に `{stem}_cwc.png` を保存 |
| クリップボードのファイルオブジェクト（Explorerでコピーしたテキストファイル） | `%TEMP%` に `{stem}_cwc.png` を保存し、CF_HDROPでファイルをクリップボードにコピー |
| クリップボードのプレーンテキスト | ファイル保存なし、生成した画像データをCF_DIBでクリップボードにコピー |

`-o`/`--output` 明示時は他コマンドと同様、指定パスへの保存のみを行いクリップボード操作はしない。

## `save_result()` の型の共通化（決定済み）

現状の `save_result()` は `loaded: LoadedImage` を受け取るが、関数の中で実際に参照しているのは
`source_path` と `source_kind` の2つだけで、`image` は使っていない。
テキスト入力の `LoadedText` も同じ2属性を持つため、**共通プロトコルを定義して受け口を広げる**。

```python
class HasSource(Protocol):
    @property
    def source_path(self) -> Path | None: ...
    @property
    def source_kind(self) -> SourceKind: ...


def save_result(
    loaded: HasSource, result: Image.Image, command: str, output: str | None
) -> Path | None: ...
```

`LoadedImage` / `LoadedText` はどちらも構造的に `HasSource` を満たすため、
既存の touka / denoise / kukiri の呼び出しコードは変更不要。
「この関数は入力の出所情報だけを見る」という意図が型として表現される。

**属性は `@property`（読み取り専用）で宣言する**。Protocol の書き換え可能な属性は不変（invariant）に
判定されるため、素の `source_kind: SourceKind` と書くと、実装側が同じ `SourceKind` で
宣言されていない限り mypy strict でエラーになる。読み取り専用にすれば共変に扱われ、
`frozen=True` のデータクラス側の宣言との組み合わせでも通る。

なお `source_kind` の値域はテキスト側で `"clipboard_text"` が増えるため、
`SourceKind` の Literal に追加する。`save_result` 側の分岐は
「`source_path` があるか」「クリップボード由来か」で判定しているため、
`clipboard_data` と `clipboard_text` を同じ扱い（ファイル出力せずクリップボードへ）にまとめられる。

## Janomeの辞書ロードコスト

Janome を遅延インポートするのは `-w` 指定時、および `-w` を自動有効化する `--hinshi` 指定時のみ。
既定の区切り文字分割経路では辞書ロードは発生せず、起動コストに影響しない。
分かち書き経路での初回ロード（数百ms〜1秒程度）は許容範囲とする。

## 依存追加まとめ

```toml
dependencies = [
    ...,
    "janome>=0.5",        # -w / --hinshi 用、遅延インポート
    "wordcloud>=1.9",
    "tokenizers>=0.15",   # --similar 用、遅延インポート
    "onnxruntime>=1.17",  # --similar 用、遅延インポート（rembg経由でも入るが直接使うので明示）
]
```

`janome` / `tokenizers` / `onnxruntime` はいずれも該当オプション指定時のみ読み込む。
既定の実行経路（区切り文字分割）では一切インポートしない。

`fastembed` はランタイム依存として**採用しない**（多数のパッケージを引き込んで
既存の `rembg` 環境と衝突するリスクがあるため）。
`scikit-learn` もランタイム依存には加えない（クラスタリングは numpy で自前実装する）が、
自前実装の正しさを確認するテスト専用の依存として `[project.optional-dependencies].dev` に追加する。

## テスト方針

既存の `tests/processing/test_{touka,denoise,kukiri}.py` と同型で、
`tests/processing/test_cwc.py` に以下を用意する:

- ファイルパス入力 → 隣に保存
- クリップボードのファイルオブジェクト入力 → TEMP保存 + クリップボードファイルコピー
- クリップボードのプレーンテキスト入力 → 保存なし + クリップボード画像コピー
- `-o` 明示時の上書き
- デフォルト分割で、連続スペース・タブ・改行が正しく区切りとして扱われること
- デフォルト分割で、句点`。`と各種かっこが区切りとして扱われること
- 読点`、`は区切られず、単語の一部として残ること
- `-w` 指定時にJanomeによる分かち書き経路に切り替わること（分割結果を固定して頻度集計を検証）
- いずれの経路でも頻度集計が期待通りか（wordcloud描画自体はモック可）
- `--hinshi 名詞` で名詞のみが集計され、他の品詞が除外されること
- `--hinshi` が複数指定（`名詞 動詞` / `名詞,動詞` の双方の書式）で効くこと
- `--hinshi` 指定時に `-w` が自動有効化されること（`-w` を渡さなくても分かち書きになる）
- `--hinshi` 指定時は基本形で集計されること（`使っ`/`使い` が `使う` に合算される）
- 未知の品詞名を渡した場合にエラー終了すること
- 正規化が分割前に効くこと（全角英数の半角化、`無し`→`なし` の表記ゆれ寄せ）
- 正規化は `--semantic` 未指定でも常時適用されること
- `--semantic` 指定時に同義語辞書で代表語へ寄せられること
  （`特になし` / `特に無し` / `ない` などが1語にまとまり、頻度が合算される）
- `--semantic` 未指定時は寄せが行われず、異表記が別語として集計されること
- 同義語辞書の解決順（同梱 → 設定ファイル → `--synonym-dict`）が効くこと
- `--no-synonym-dict` で寄せが無効化されること
- 同義語辞書が見つからない場合、エラー終了せず警告ログを出して続行すること
- `--similar` で文分割が句点・改行・`！`・`？` で行われること
- `--similar` でクラスタごとの件数が頻度になること
  （埋め込みモデルはモックし、既知のベクトルを返させてクラスタリング結果を検証）
- `--similar` の代表文選択が「最頻 → 同数なら最短」の規則に従うこと
- `--similar-threshold` の変更でクラスタのまとまり方が変わること
- `--similar` と `--semantic` / `-w` / `--hinshi` の同時指定がエラーになること
- `--semantic` と `-w` / `--hinshi` の同時指定がエラーになること
- `--similar-max-length` の既定10文字で代表文が切り詰められ末尾に`…`が付くこと
- `--similar-max-length 0` で切り詰めが行われないこと
- 切り詰めの有無でクラスタのまとまり方が変わらないこと（切り詰めは描画直前のみ）
- UTF-8のファイルが読めること（BOM付き/なしの双方）
- CP932のファイルがフォールバックで読めること
- `--encoding` 明示時はフォールバックせず、読めなければエラー終了すること
- CRLF/CRの改行がLFに統一され、`単語\r`のような語が生まれないこと
- 集計対象が0件（空入力、全語ストップワード）の場合にエラー終了すること
- `--similar` 未指定時は tokenizers / onnxruntime をインポートしないこと
- 自前のクラスタリングが、既知のベクトル集合に対して期待通りのクラスタを返すこと
  （閾値ちょうど・閾値未満・閾値超過の境界を含める）
- 自前クラスタリング（Lance-Williams更新式）の結果が、
  `scikit-learn`（`metric="cosine"`, `linkage="average"`）と一致すること
  （`dev`依存の`scikit-learn`を使い、複数パターンのベクトル集合で突き合わせる）
- キャッシュ済みモデルがある場合はダウンロードを行わないこと
- モデルのダウンロード失敗時に、接続先URLを含むエラーで終了すること
- デフォルトストップワード（「こと」「する」「の」等）が集計から除外されること
- `--stopwords` 指定分（カンマ区切り）がデフォルトリストに追加されること
- `--stopwords-file` 指定分（ファイル）がデフォルトリストに追加されること
- `--no-default-stopwords` 指定時に日本語リストと英語`STOPWORDS`の双方が効かなくなること
- 英語のストップワード（`the`等）が自前の除去処理で落ちること
  （`generate_from_frequencies()`は`stopwords`を見ないため、ライブラリ任せにできない）
- `--similar` の文単位経路ではストップワードが適用されないこと
- Explorerでコピーしたテキストファイルが `source_kind="clipboard_file"` になること
  （`"path"` にはならず、出力が`%TEMP%`+クリップボードコピーになる）
- 設定・オプションいずれもない場合、同梱の `data/user.dic` がTokenizerに渡ること
- 設定ファイルの `[cwc] user_dict` が同梱辞書を上書きすること
- `--user-dict` 指定時に同梱辞書・設定ファイルの双方を上書きすること
- `--no-user-dict` 指定時にユーザー辞書が一切渡らないこと
- 設定ファイルなし／`[cwc]`セクションなしでも同梱辞書で正常動作すること
- 明示指定された辞書ファイルが存在しない場合、エラー終了せず警告ログを出して続行すること
- 同梱辞書が欠落していてもエラーにならず辞書なしで動作すること
