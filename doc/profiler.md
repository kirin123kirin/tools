# profiler コマンド設計ドラフト

> **状態: ドラフト（未確定）** — 末尾の未決事項を確定させてから実装に入る。

## 概要

表形式データの**各列を「使えるかどうか」の観点で棚卸しする** `tools profiler` サブコマンド。

解決したい問題:

- 受け取ったデータの各列に、どれくらい欠損があるのか分からない
- どの列が一意なのか、主キーとして使えるのか分からない
- どんな値が多いのか、外れ値が混ざっていないか知りたい
- Excelで開いて目視でカウントするのは、列数・行数が多いと現実的でない

サブコマンド名・単体エントリーポイント名ともに `profiler`
（`pyproject.toml` の `[project.scripts]` に `profiler = "tools.cli:run_as_subcommand"` を追加）。

## 出力する指標

列ごとに1行を出力する。

| 列 | 内容 |
|---|---|
| `source` | 入力元（ファイル名、またはクリップボードを表す文字列） |
| `sheet` | Excelのシート名（**Excelを入力に含むときだけ出力する**。後述） |
| `column` | 列名（ヘッダーがない場合は0始まりの列番号） |
| `rows` | 行数（ヘッダー行を除く） |
| `filled` | 値が入っている行数 |
| `empty` | 空の行数 |
| `fill_rate` | 充填率（`filled / rows`） |
| `unique` | ユニークな値の数 |
| `unique_rate` | 一意率（`unique / rows`） |
| `is_filled` | 全行埋まっているか（真偽値） |
| `is_unique` | 全行一意か（真偽値） |
| `key_score` | **主キーらしさのスコア**（後述） |
| `top` | 出現頻度の上位N件（既定10件）。書式は後述 |

### sheet列を出す条件

**入力にExcelを1つでも含むときだけ `sheet` 列を出力する。**
CSV/TSV/JSONのみのときは列自体を出さない（常に空の列が並ぶのを避けるため）。

複数ファイルを指定して一部だけExcelの場合は列を出し、Excel以外の行では空にする。

### top列の書式

`値(件数)` を**前後に空白を入れたスラッシュ**（` / `）で区切る。

```text
東京(120) / 大阪(80) / 名古屋(45)
```

- 件数を併記するのは、どれくらい偏っているかが分かるようにするため
- 区切りを「空白＋スラッシュ＋空白」とするのは、値自体に `/` が含まれる場合
  （日付 `2026/07/26`、パス `C:/work` 等）と見分けやすくするため。
  完全な区別は保証しないが、実用上これで足りる
- `--top 0` のときは空文字にする

### 空とみなす値

以下を「空」として数える。

```text
None, "", "N/A", "NULL", "null", "None", "none", "-", "NaN"
```

- 前後の空白のみの文字列（`"  "`）も空として扱う
- `--empty-values` で**この一覧を置き換える**（追加ではなく差し替え）
- `--no-default-empty-values` で既定の一覧を無効化し、`None`と空文字だけを空とする

### key_score（主キーらしさ）

**充填率と一意率の調和平均**とする。

```text
key_score = 2 * fill_rate * unique_rate / (fill_rate + unique_rate)
```

- 両方1.0のとき 1.0、どちらかが0のとき 0.0 になる
- 片方だけ高くても上がらない（「全部埋まっているが値が3種類だけ」の列は低評価）
- **複合キーの推定は行わない。** スコアを見て利用者が判断する
  （列数が多いと組み合わせ爆発するため、ツール側では踏み込まない）

## 入力

### 入力元: ファイルとクリップボードの両方

```powershell
profiler data.csv              # ファイル
profiler *.xlsx                # グロブ・複数指定
profiler a.csv b.tsv           # 複数ファイル
profiler                       # 引数なし → クリップボードのTSVを読む
```

- **引数なしのときクリップボードを読む。** Excelでセル範囲をコピーした直後に
  そのままプロファイルできる（`mdtsv` と同じく、Excelのコピーは
  `CF_UNICODETEXT` にTSVが入るため、これをそのまま扱う）
- 既存の `common/clipboard.py` の `get_clipboard_text()` を再利用する
- クリップボード入力時、`source` 列は `(clipboard)` とする

### 対応する形式

| 形式 | 判定方法 | 備考 |
|---|---|---|
| CSV | 拡張子 `.csv` | 区切りは `,` |
| TSV | 拡張子 `.tsv` / `.txt`、またはクリップボード | 区切りは `\t` |
| Excel | 拡張子 `.xlsx` | **シートごとに個別集計**する |
| JSON | 拡張子 `.json` / `.jsonl` | 後述 |

- 区切り文字は `--sep` で明示指定できる（拡張子による判定を上書き）
- `.xls`（旧形式）は対応しない
- エンコーディングは `common/textfile.py` の `read_text_with_fallback()`
  （UTF-8 → CP932 フォールバック）を使う

#### JSONの扱い

2つの形を受け付ける。

- **オブジェクトの配列**: `[{"a": 1, "b": 2}, {"a": 3, "b": 4}]`
  → キーを列名、各要素を行として扱う
- **JSON Lines**: 1行1オブジェクト（`.jsonl`）
  → 同様に扱う

いずれも**ネストは展開しない**。値がオブジェクトや配列の場合は、
JSON文字列として1つの値とみなす（フラットな表として集計する）。
全要素に共通しないキーは、その行では空として数える。

### ヘッダー行

- 既定では**1行目をヘッダーとして扱う**
- `--no-header` でヘッダーなしとし、列名を0始まりの番号にする
- `--header N` でN行目（0始まり）をヘッダーとする
  （N行目より前の行は読み捨てる。装飾行があるExcelのため）

## 出力

### 出力先

```powershell
profiler data.csv                    # 標準出力にTSV
profiler data.csv -o profile.tsv     # TSVファイル
profiler data.csv -o profile.xlsx    # Excel（書式付き）
profiler data.csv --view             # ブラウザでHTML表示
profiler data.csv --clip             # 結果をクリップボードにTSVでコピー
```

- 既定は標準出力にTSV
- **`--clip` 指定時は標準出力に結果を出さず**、クリップボードにのみ入れて
  「コピーしました」程度の短いメッセージだけ表示する
  （既存の `clip*` 系コマンドと同じ方針）
- `--view` はブラウザでHTML表示する（`clipview` と同じ方式で
  `%TEMP%` に固定名で書き出し、キャッシュバスター付きURLで開く）

### Excel出力時の書式

`--output *.xlsx` のときのみ。読み手が問題のある列にすぐ気づけるようにする。

- ヘッダー行を太字・中央揃え・罫線付きにし、オートフィルタを設定する
- **`is_filled` / `is_unique` が偽のセルを薄い赤で塗る**（欠損・重複がある列）
- `fill_rate` / `unique_rate` / `key_score` はパーセント or 小数2桁で表示する
- 依存は `xlsxwriter`。`.xlsx` 出力時のみ遅延インポートする

### HTML表示時の体裁

`clipview` の方針に合わせる。

- CSSは埋め込み（外部CDNを使わずオフラインで動く）
- ダークモード対応（`prefers-color-scheme`）
- 表に罫線、ヘッダー固定、`is_filled`/`is_unique` が偽の行を強調
- `top` の値は長くなりがちなので、セル内で折り返すか省略する

## 実装方針（処理時間を最優先する）

このコマンドは**処理時間の短縮を最優先課題**として設計する。以下は実測に基づく判断。

### 集計は「転置してから列ごとにCounter」を使う（実測済み）

100万行×10列で3方式を比較した。

| 方式 | 時間 | 備考 |
|---|---|---|
| 転置（`zip_longest`）してから列ごとに`Counter` | **0.71秒** | 採用 |
| 最初から列方向データがある場合の直接集計 | 0.54秒 | CSVは行方向で読むため転置は避けられない |
| 行を1回ループし全列を同時に`Counter`で集計 | 1.11秒 | **転置方式の約1.6倍遅い** |

**「行ループ1回で全列同時集計」の方が直感的だが、実測では遅い。**
Pythonではループの重層度（内側ループで列ごとに分岐する）よりも、
列ごとに独立した単純なループを回す方がインタプリタのオーバーヘッドが小さいため。
**列ごとに`Counter(v for v in col if v not in empty_vals)`を回す方式を採用する。**

### Excel読み込みが最大のボトルネック（実測済み）

10万行×8列のExcelで比較した。

| 方式 | 時間 |
|---|---|
| `openpyxl.load_workbook()`（既定） | 6.54秒 |
| `openpyxl.load_workbook(read_only=True)` | 4.77秒（**27%高速化**） |
| （参考）同規模のCSVをcsvモジュールで読む | 0.03秒 |

**Excelは同じ行数のCSVと比べて2桁遅い。** `read_only=True` は必須とし、
Excel入力を選んだ時点で「CSVより大幅に時間がかかる」ことを利用者に
ログで伝える（進捗ログの要否は末尾の未決事項）。

- `read_only=True` + `iter_rows(values_only=True)` で1行ずつイテレータ処理する
  （全行をリスト化せず、集計側も1パスで受けられるようにする）
- **Excelでも集計本体は「転置してから列ごとにCounter」を使う。**
  1シート分をメモリに載せてから転置するため、シートが極端に大きい場合は
  メモリ使用量とのトレードオフになる（未決事項参照）
- 依存はすべて**遅延インポート**する（`openpyxl`/`xlsxwriter` は
  該当形式のときだけ読み込み、他コマンドの起動を遅くしない）

### 気をつけること

- **0行のデータでゼロ除算しない。** 空ファイル・ヘッダーのみのファイルは
  明示的なエラーで終了する（`fill_rate` の分母が0になるため）
- **全列が空のデータでも落ちない**

### 値の正規化

集計前に、値を**文字列に正規化してから比較する**。

- **小数部が0の数値は整数として扱う。** Excelのセルは書式によって
  `1` が `1.0` として読まれることがあり、これを別の値として数えると
  ユニーク数が実態とずれるため（`1.0` → `"1"`）
- 前後の空白は除去する（`"東京 "` と `"東京"` を同じ値とする）
- 上記以外の型変換はしない。`True` と `"True"` のような差は残る
  （元データの実態を潰しすぎないため）

## セキュリティ方針との整合（CLAUDE.md）

- 読み込みは標準ライブラリと `openpyxl` / `xlsxwriter` の公開APIのみ
- クリップボードの読み書きは `common/clipboard.py` 経由（公開API）で、実行時に1回だけ
- 外部通信は発生しない（すべてローカル処理）
- 読み込み元・出力先・スキップした列や行があればログに出す

## 他コマンドとの関係

| コマンド | 役割 |
|---|---|
| `profiler` | 表形式データの**各列の統計プロファイル**を出す |
| `mdtsv` | Markdownの表 ↔ TSV の**形式変換** |
| `clipview` | Markdown/HTML を**ブラウザで表示** |

Excelからコピーした範囲をそのままプロファイルしたい場合は `profiler` を引数なしで実行する。

## テスト方針

`tests/processing/test_profiler.py` に用意する。

### 集計ロジック

- 全行同じ値の列で `is_unique` が偽、`is_filled` が真になること
- 全行異なる値の列で `is_unique` が真になること
- 空とみなす値（`""` / `"N/A"` / `None` / 空白のみ）が `empty` に数えられること
- `--empty-values` で判定対象が差し替わること
- `--top N` で上位N件に絞られること（`--top 0` で空）
- **行長がばらついても列がずれず、不足分が空として数えられること**
- **0行のデータでゼロ除算にならず、明示的なエラーになること**
- 全列が空のデータでも落ちないこと

### 値の正規化のテスト

- **`1.0` と `1` が同じ値として数えられること**（Excel由来の型ゆれ対策）
- `1.5` は `1` に丸められず別の値であること
- 前後に空白がある値（`"東京 "`）と無い値（`"東京"`）が同じ値になること
- `True` と `"True"` は別の値のままであること

### key_score のテスト

- `fill_rate` と `unique_rate` がともに1.0のとき `key_score` が1.0になること
- どちらかが0のとき0.0になること
- 片方だけ高い列より、両方が中程度の列の方が高くなること（調和平均の性質）

### 入力のテスト

- CSV / TSV が読めること
- CP932のCSVがフォールバックで読めること
- `--sep` が拡張子による判定を上書きすること
- **Excelの複数シートがシートごとに別レコードとして出ること**
- JSONの**オブジェクト配列**が読めること
- **JSON Lines** が読めること
- JSONのネストした値がJSON文字列として1値になること
- JSONで一部の要素にないキーが、その行では空になること
- **引数なしでクリップボードのTSVが読まれること**
- `--no-header` で列名が番号になること
- `--header N` でN行目がヘッダーになり、それより前が読み捨てられること
- 非対応形式（`.pptx` 等）で明示的なエラーになること

### 出力のテスト

- 既定でTSVが標準出力に出ること
- `-o *.tsv` / `-o *.xlsx` で形式が切り替わること
- **`--clip` でクリップボードに入り、標準出力には結果が出ないこと**
  （短い完了メッセージのみ出ること）
- `--view` でHTMLが書き出され、ブラウザ起動が呼ばれること
- 複数ファイル指定時、`source` 列で区別できること
- ヘッダー行が1度だけ出ること（ファイルごとに重複しないこと）
- **`openpyxl` / `xlsxwriter` が該当形式以外ではインポートされないこと**

### sheet列とtop列の書式

- **入力にExcelを含まないとき `sheet` 列自体が出力されないこと**
- 入力にExcelを含むとき `sheet` 列が出て、Excel以外の行では空になること
- `top` が `値(件数) / 値(件数)` の形式（スラッシュの前後に空白）になること
- `top` が頻度の多い順に並ぶこと
- 値に `/` が含まれていても出力が壊れないこと（`2026/07/26` 等）
- `--top 0` で `top` が空文字になること

## 未決事項

1. **巨大ファイルでの実行時間**
   数百万行規模でどこがボトルネックになるか実測が必要。
   進捗表示（`--verbose`）を付けるかも含めて実装時に判断する。

2. **Excelの数式セルの扱い**
   `openpyxl` は既定で数式文字列（`=SUM(A1:A9)`）を返す。
   計算結果を見たい場合は `data_only=True` が必要だが、
   Excelで保存していないファイルでは値がキャッシュされておらず `None` になる。
   どちらを既定にするか、実データで確認して決める。
