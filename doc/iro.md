# iro コマンド設計書

## 概要

現在開いているプレゼンテーション全体に対して、以下を一括で行う
`tools iro` サブコマンド。「色」から。

1. **既存スライドの独自色化**: テーマカラー（アクセント1〜6等）を
   参照している既存シェイプ・テキストの色を、現在の見た目のまま
   RGB固定値に変換する（テーマカラーを後で変えても既存の見た目が
   変わらないようにする）
2. **テーマカラーの変更**: アクセント1〜6を新しい配色に変更する
3. **既定書式の一時適用**: シェイプ・矢印（コネクタ）・テキストボックスを
   1つずつ新規作成して指定の書式を適用し、CommandBars経由で
   「既定の図形として設定」を試みる（実行したそのセッション限りの
   一時的な既定値。PowerPointを再起動すると失われる）

サブコマンド名・単体エントリーポイント名ともに `iro`
（`pyproject.toml` の `[project.scripts]` に
`iro = "workpytools.cli:run_as_subcommand"` を追加）。
短く叩きやすい名前を優先している（`vv`/`ikko`/`seiretsu`と同じ流儀）。

引数はない。実行するたびに、現在開いているプレゼンテーション全体に対して
常に同じ3ステップ（独自色化→テーマカラー変更→既定書式適用）を行う。

## 背景・動機

社内で作る資料の配色を、以下のような「深緑×レンガ色×グレー」の
対比配色に統一したいという要望から生まれた。

- テーマのアクセントカラーに、実務でよく使う配色（メイン色・対比色・
  ニュートラル色）をあらかじめ登録しておき、新規に描く図形やグラフが
  自動的にこの配色に従うようにしたい
- ただし、**すでに存在するスライドの見た目を勝手に変えたくない**。
  既存スライドの図形がテーマカラーを参照している場合、テーマの
  アクセントカラーを変更すると、その図形の色も連動して変わって
  しまう。これを防ぐため、テーマカラーを変更する前に、既存スライドの
  色を「今の見た目のまま」で固定（独自色化）しておく
- さらに、シェイプ・矢印・テキストボックスをよく使う書式
  （線の色・太さ、フォント、オートフィット、折り返し）で統一したい

## 新テーマカラー（アクセント1〜6）

| 項目 | HEX | 説明 |
| --- | --- | --- |
| アクセント1 | `#1E7145` | 深緑（基準色） |
| アクセント2 | `#5A9B78` | アクセント1を薄めた緑 |
| アクセント3 | `#A8493D` | レンガ色（基準色） |
| アクセント4 | `#C57F76` | アクセント3を薄めたレンガ色 |
| アクセント5 | `#808080` | グレー（基準色） |
| アクセント6 | `#BFBFBF` | アクセント5を薄めたグレー |

「テキスト/背景」4色（濃色1・淡色1・濃色2・淡色2）・ハイパーリンク色は
変更しない（アクセント1〜6のみを対象にする）。

## 実行順序

**必ず「独自色化 → テーマカラー変更 → 既定書式適用」の順で行う。**
順序を逆にすると、独自色化の時点でテーマカラーがすでに新しい配色に
変わってしまっており、「今の見た目のまま固定」ができなくなる
（新しい配色で固定されてしまい、既存スライドの見た目が変わってしまう）。

```text
1. 全スライドの全シェイプ（グループ内を再帰的に含む）を走査し、
   テーマカラーを参照している色をRGB固定値に変換する
2. テーマのアクセント1〜6を新しい配色に変更する
3. サンプル図形（シェイプ・矢印・テキストボックス）を作成し、
   指定の書式を適用してから「既定の図形として設定」を試みる
```

## ステップ1: 既存スライドの独自色化

### 対象範囲

`merioall`と同じ走査方針を使う。

- 全スライド上の全シェイプ（`HasTextFrame`の有無を問わない）
- グループ化されたシェイプは`GroupItems`を再帰的に辿り、内部の
  シェイプも対象にする
- スライドマスター・スライドレイアウトは対象**外**（テーマ参照の
  「参照元」であり、独自色化してしまうとテーマ変更の効果が
  マスター自身に反映されなくなるため）
- 表・SmartArt等の特殊オブジェクトは対象外
  （`HasTextFrame`や`Fill`/`Line`にアクセスできる通常のシェイプのみ）

### 対象にする色の種類

以下の3種類の色プロパティを対象にする。

| 対象 | プロパティ |
| --- | --- |
| 図形の塗りつぶし色 | `Shape.Fill.ForeColor` |
| 図形の枠線色 | `Shape.Line.ForeColor` |
| テキストの文字色 | `Shape.TextFrame.TextRange.Font.Color` |

### 判定・変換方法

各色オブジェクト（`ColorFormat`）は`.Type`プロパティで
`msoColorTypeRGB`（値`1`）か`msoColorTypeSchemeColor`（値`2`、
テーマカラー参照）かを判定できる。

```text
for 対象色 in [Fill.ForeColor, Line.ForeColor, Font.Color]:
    if 対象色.Type == msoColorTypeSchemeColor:
        現在のRGB値 = 対象色.RGB  # 参照先の実際の色を読み取る
        対象色.RGB = 現在のRGB値  # RGB値を再代入すると参照が解除され固定値になる
```

- `ColorFormat.RGB`を読み取ると、テーマ参照中でも**現在表示されている
  実際のRGB値**が返る（PowerPoint COMの仕様）
- その値をそのまま`.RGB`に再代入すると、`.Type`が
  `msoColorTypeRGB`に変わり、テーマカラーとの参照関係が切れる
  （見た目は代入前後で変化しない）
- `Fill.Visible`が偽（塗りつぶしなし）の場合や、`Line.Visible`が
  偽（線なし）の場合は、その色プロパティへのアクセスが例外に
  なることがあるため、`Visible`を確認してからアクセスする
- テキストが空（`TextRange.Text`が空文字列）の場合、`Font.Color`の
  操作はスキップする（`merioall`と同じ判断基準）

### 変更しないもの

- シェイプの位置・サイズ・形状・個数
- テーマカラー自体（この時点ではまだ変更しない。ステップ2で変更する）
- RGB固定値の色（すでに`msoColorTypeRGB`の色はそのまま。RGB値の
  再代入自体は行っても値は変わらないため実質的な影響はない）

## ステップ2: テーマカラーの変更

`merioall`の`_apply_theme_fonts`と同じ`Designs`走査パターンを使う。

```text
for design in presentation.Designs:  # Count + Item(i) でアクセス
    color_scheme = design.SlideMaster.Theme.ThemeColorScheme
    color_scheme(ppAccent1).RGB = 0x00457137  # #1E7145 相当の値
    color_scheme(ppAccent2).RGB = ...
    color_scheme(ppAccent3).RGB = ...
    color_scheme(ppAccent4).RGB = ...
    color_scheme(ppAccent5).RGB = ...
    color_scheme(ppAccent6).RGB = ...
```

- `ThemeColorScheme`はインデックス（`ppAccent1`=5 〜 `ppAccent6`=10、
  `MsoThemeColorSchemeIndex`列挙体）でアクセスするコレクション
- 複数デザイン（セクションごとに別テーマ）を使っている場合に備え、
  `merioall`と同様に`Designs`配下の全マスターのテーマを対象にする
- HEXからPowerPointのRGB値（`0x00BBGGRR`形式の整数、`RGB(r,g,b)`関数
  相当）への変換は`common/`に純粋関数として切り出す

### RGB値の変換（HEX→PowerPointのRGB整数）

PowerPoint COMの`.RGB`プロパティは`0x00BBGGRR`という並び順の整数を
期待する（Win32 APIの`COLORREF`と同じ、R/G/Bの並びが逆順）。

```python
def hex_to_ppt_rgb(hex_color: str) -> int:
    r, g, b = int(hex_color[0:2], 16), int(hex_color[2:4], 16), int(hex_color[4:6], 16)
    return (b << 16) | (g << 8) | r
```

## ステップ3: 既定書式の一時適用

### 3種類のサンプル図形と書式

| 対象 | 線 | フォント | オートフィット | 折り返し |
| --- | --- | --- | --- | --- |
| シェイプ（四角形） | 黒・1pt | メイリオ | なし（`ppAutoSizeNone`） | あり（`WordWrap = msoTrue`） |
| 矢印（直線コネクタ） | 黒・2pt | — | — | — |
| テキストボックス | なし | メイリオ・12pt・黒 | 枠に合わせて図形のサイズを変更する（`ppAutoSizeShapeToFitText`） | なし（`WordWrap = msoFalse`） |

- シェイプは`msoShapeRectangle`を1つ、現在のアクティブスライド外
  （画面に映らない一時的な位置、例えば負の座標）に作成して書式を適用する
- 矢印は`msoConnectorStraight`（`AddConnector`）を1つ作成する
- テキストボックスは`AddTextbox`で1つ作成する
- いずれも書式適用後、サンプル図形を選択した状態で
  「既定の図形として設定」に相当する操作を行い、その後**サンプル
  図形自体は削除する**（既定値だけを残し、見た目に不要な図形を
  スライドに残さない）

### 「既定の図形として設定」の実行方法

PowerPoint COMには「既定の図形として設定」を直接呼び出す専用APIが
存在しない。`Application.CommandBars`経由でUIのボタン（コントロールID）
を`Execute()`することで、ユーザー操作と同じ効果を再現する。

```text
shape.Select()
commandbar_control = app.CommandBars.FindControl(Id=<既定の図形として設定のID>)
commandbar_control.Execute()
```

- コントロールIDはPowerPointのバージョン・言語設定によって変わりうる
  ため、**呼び出しに失敗した場合は例外を捕捉し、処理全体は継続した
  うえで「既定書式の一時適用に失敗しました。手動で図形を選択し、
  右クリック→『既定の図形として設定』を行ってください」という
  警告を出す**（ステップ1・2の結果は既定書式適用の成否に関わらず
  保持される）
- **この既定値はPowerPointを再起動すると失われる。** ファイルには
  保存されない一時的な状態であることをヘルプ文言・出力メッセージに
  明記する

### サンプル図形の後始末

書式適用・既定化の試行が成功しても失敗しても、作成したサンプル図形
（シェイプ・矢印・テキストボックスの3つ）は必ず削除する
（`try`/`finally`で保証する）。削除に失敗した場合はエラーメッセージに
含めるが、処理全体を止めない。

## エラー処理

- PowerPointが起動していない場合: 「PowerPointでプレゼンテーションを
  開いた状態で実行してください」と表示してエラー終了する（新規起動はしない）
- プレゼンテーションが開かれていない場合: 同様にエラー終了する
- ステップ1・2（独自色化・テーマカラー変更）でCOM例外が発生した場合:
  例外内容を含めたエラーメッセージで終了する。`StartNewUndoEntry()`に
  より、Ctrl+Zで開始前の状態に戻せる旨をメッセージに含める
- ステップ3（既定書式の一時適用）の失敗は**致命的エラーとしない**。
  ステップ1・2が成功していれば、コマンド全体としては正常終了
  （終了コード`0`）とし、標準出力に警告メッセージを添える

## 元に戻す（Undo）

`merioall`と同じ理由で、**ステップ1・2の処理を開始する直前に
`Application.StartNewUndoEntry()`を必ず呼ぶ。** ステップ3
（既定書式の一時適用）はファイルに保存されない一時状態のため、
Undo対象に含める必要はない（サンプル図形の作成・削除も含めてUndo
境界の外で行うか、境界を分けて別途処理する）。

## 出力・ログ

処理内容を`common/logging.py`経由でログに出す。

- 独自色化した色の件数（塗りつぶし・枠線・文字色それぞれ）
- テーマカラーを変更したデザイン（マスター）の件数
- 既定書式の一時適用が成功したか、失敗して警告を出したか

完了時に標準出力へサマリを表示する
（例: `既存スライドの色を32件独自色化し、テーマカラーを新配色に変更しました
（デザイン1件）。シェイプ・矢印・テキストボックスの既定書式を一時適用しました
（このセッション限り、PowerPoint再起動で失われます）`）。

## セキュリティ方針との整合（CLAUDE.md）

- **COM操作は`pywin32`の公開APIのみ**を使う。生のWindowsフック・
  メモリ改ざん・プロセスインジェクションは行わない
- `CommandBars.FindControl`/`Execute()`もPowerPoint公式のCOM API
  であり、UIの自動操作ではあるが、キー入力の自動送信やグローバル
  キーフックとは異なる（ユーザーが右クリックメニューから選ぶ操作を
  プログラムから呼び出しているだけ）
- **常駐・バックグラウンド監視をしない。** 実行のたびに1回だけ
  対象を処理して終了する
- **外部通信は発生しない**（すべてローカルのPowerPointへのCOM操作のみ）
- 何件の色を独自色化し、テーマカラーをどう変更したかを
  `common/logging.py`経由でログに出す

## 他コマンドとの関係

- `merioall`（和文フォントの統一）と組み合わせて使うことを想定している。
  どちらも「プレゼンテーション全体を一括で整える」という性質が同じで、
  実行順序はどちらが先でも結果は変わらない
- `merioall`のシェイプ走査パターン（`Designs`/`Slides`/`CustomLayouts`
  をCount+Item(i)でアクセスし、グループを再帰的に辿る）をそのまま
  再利用する

## テスト方針

HEX→PowerPoint RGB整数変換、新テーマカラーの定義は、COM非依存の
純粋関数として`common/`配下に切り出し、`tests/common/`でテストする。
`tests/processing/test_iro.py`ではPowerPoint COMオブジェクトを
`MagicMock`でモックする。

### 独自色化（ステップ1）

- テーマカラー参照（`msoColorTypeSchemeColor`）の色が、現在の
  RGB値を保ったままRGB固定値に変換されること
- すでにRGB固定値の色は、値が変化しないこと（再代入されても
  実害がないこと）
- `Fill.Visible`/`Line.Visible`が偽の場合、そのプロパティへの
  アクセスをスキップし例外にならないこと
- テキストが空のシェイプでは`Font.Color`の操作をスキップすること
- グループ化されたシェイプの内部（`GroupItems`）も再帰的に
  独自色化されること
- スライドマスター・レイアウトは独自色化の対象に**含まれない**こと

### テーマカラー変更（ステップ2）

- `ThemeColorScheme`のアクセント1〜6に、指定したHEX値に対応する
  RGB整数が設定されること
- 複数デザイン（`Designs.Count > 1`）がある場合、全てのデザインの
  テーマが変更されること
- HEX→PowerPoint RGB整数の変換関数が、既知の入力に対して正しい
  値を返すこと（例: `#1E7145` → `0x00457137`）

### 既定書式の一時適用（ステップ3）

- シェイプ・矢印・テキストボックスの3種類それぞれについて、
  指定の書式（線の色・太さ、フォント、オートフィット、折り返し）が
  サンプル図形に適用されること
- `CommandBars`経由の既定化呼び出しが例外を送出した場合、処理全体は
  異常終了せず、警告メッセージを伴って正常終了すること
- サンプル図形が、既定化の成否によらず必ず削除されること

### 実行順序

- 独自色化がテーマカラー変更より先に行われること
  （順序が逆だと独自色化の結果が新しいテーマカラーになってしまう
  ことの検知）

### エラー処理

- PowerPointが起動していない場合、新規起動を試みずエラー終了すること
- プレゼンテーションが開かれていない場合にエラー終了すること
- ステップ1・2でのCOM例外時に、Ctrl+Zで戻せる旨を含むエラー
  メッセージが出ること
